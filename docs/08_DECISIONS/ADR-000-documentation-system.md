# ADR-000 — документация проекта

**Status: Accepted.** Зафиксировано: 2026-10-12.

**Source:** владелец одобрил план системы документации и поручил поэтапно её создать.

## Контекст

Архитектурные идеи находились преимущественно в чатах, README почти пуст. Требуются понятная структура, возвращение после перерыва, восстановление на другом оборудовании и независимость от памяти помощника.

## Решение

Документация хранится в docs основного репозитория ANIMA. Канонические форматы — Markdown и Mermaid. Связи между документами — обычные относительные Markdown-ссылки.

VS Code — основной инструмент работы с проектом. Obsidian открывает docs как дополнительный vault. Специальные плагины не являются обязательной зависимостью.

Входные страницы: START_HERE, AI_CONTEXT, Project_Status, System_Map и Module_Index. Этапы имеют зависимости и критерии завершения. У модулей раздельно отражаются согласование замысла и готовность реализации.

Accepted ADR и проверенный код имеют приоритет перед памятью чата в своей области. Расхождение фиксируется, а не скрывается.

## Последствия

Описание затронутых модулей, статус и этап обновляются вместе с кодом. Проверки выбираются по изменению: для документации — ссылки/реестр; для поведения — соответствующий сценарий. Не добавляем фиктивные тесты ради галочки.

Новый помощник может восстановить контекст из репозитория. Обновление документации остаётся обязанностью разработчика; красивый граф не гарантирует её достоверность.

## Открытые вопросы

Будущая сборка сайта и дополнительная автоматизация выбираются по потребности. Они не блокируют текущий workflow.
