# Архитектурные решения

ADR отвечает на вопрос: почему мы выбрали это направление и какие последствия принимаем.

| ID | Решение | Статус |
|---|---|---|
| [ADR-000](ADR-000-documentation-system.md) | Документация в основном репозитории, Markdown/Mermaid, VS Code/Obsidian | Accepted |
| [ADR-001](ADR-001-instance-continuity.md) | Непрерывность через переносимые данные экземпляра | Accepted |
| [ADR-002](ADR-002-fast-deep.md) | Fast/Deep и автономный переносимый Fast | Accepted |
| [ADR-003](ADR-003-local-reinforcement.md) | Локальная оптимизация периферии отдельно от регуляции личности | Accepted |

## Правила

Accepted означает принятый принцип или решение с явно указанным охватом. Оно не означает, что соответствующий код или оборудование готовы.

Черновик ADR имеет статус Draft. При замене решения прежний документ получает Superseded и ссылку на новый; причина и история не удаляются. Уточнение принятого решения не должно незаметно менять его смысл.

Начальный перенос обсуждений выполняется 2026-10-12. На страницах указан источник согласования; детали, которые не были приняты, оставлены открытыми.

```markdown
## Связи
```

Важное новое решение принимает владелец проекта. Рутинные правки документации в согласованном направлении не требуют отдельного ADR.
