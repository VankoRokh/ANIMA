# Архитектурные решения

ADR отвечает на вопрос: почему выбрано направление и какие последствия мы принимаем.

| ID | Решение | Статус |
|---|---|---|
| [ADR-000](ADR-000-documentation-system.md) | Первая система документации | Superseded |
| [ADR-001](ADR-001-instance-continuity.md) | Непрерывность через переносимые данные экземпляра | Accepted |
| [ADR-002](ADR-002-fast-deep.md) | Fast/Deep и автономный переносимый Fast | Accepted |
| [ADR-003](ADR-003-local-reinforcement.md) | Локальная оптимизация периферии отдельно от регуляции личности | Accepted |
| [ADR-004](ADR-004-documentation-workflow.md) | Один факт — одно каноническое место; разделение status/history/test evidence | Accepted |

## Правила

Accepted означает принятый принцип, но не готовую реализацию. Draft — обсуждаемое решение. При замене прежний ADR получает Superseded и ссылку на новый; история не удаляется.

Новый ADR нужен только для решения, которое меняет архитектуру, правила проекта или создаёт существенные долгосрочные последствия. Рутинные правки не требуют ADR.
