# ADR-001 — данные экземпляра и непрерывность

**Status: Accepted.** Зафиксировано: 2026-10-12.

**Scope:** принцип переносимости данных; окончательная схема Identity и миграций не утверждается.
**Source:** обсуждения ANIMA о сменяемых компонентах и модуле личности; требования восстановления в текущем плане.

## Контекст

Код общего проекта и опыт конкретного экземпляра имеют разное назначение. Публичный репозиторий не должен становиться хранилищем персональных журналов.

## Решение

Исходники и документация версионируются вместе. Состояние, история и другие данные экземпляра резервируются отдельно и переносятся при замене оборудования.

Сейчас экземпляр использует `state.json`, `identity.json`, `events.jsonl` и `memories.jsonl` внутри выбранного каталога данных. По умолчанию это `<project>/data`; каталог может быть перенаправлен через `ANIMA_DATA_DIR`. Локальные данные экземпляра исключаются из Git. Код anima/memory остаётся частью репозитория.

Новый запуск без data создаёт новое состояние. Для продолжения прежнего экземпляра требуется восстановление его данных. Сменный физический носитель — долгосрочное направление.

## Последствия

Клонирование репозитория восстанавливает проект, но не историю экземпляра. Процедура резервирования должна проверяться восстановлением.

Замена модели требует фиксации её версии и конфигурации; одинаковые данные не гарантируют одинаковое поведение разных моделей.

## Открытые вопросы

Минимальный уникальный `instance_id` и явное расположение каталога данных уже реализованы. Расширенная версия схемы, миграции между несовместимыми схемами, одновременная работа копий, правила происхождения и горячее извлечение носителя остаются Draft.
