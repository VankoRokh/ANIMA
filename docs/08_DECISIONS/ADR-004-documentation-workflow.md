# ADR-004 — упрощённый workflow документации

**Status: Accepted.**

## Контекст

Первая версия документационной системы успешно вынесла контекст проекта из чатов в репозиторий, но создала слишком много живых страниц со статусами и обязанность синхронно обновлять одни и те же факты. `Project_Status`, `Current_Stage`, Stage-файлы и карточки модулей начали частично выполнять одинаковые функции.

## Решение

Ввести правило «один факт — одно каноническое место».

- `Project_Status.md` — единственный текущий рабочий статус.
- Roadmap/Stage — цели, порядок, критерии и проверки этапов, но не ежедневный статус.
- Git — история изменений вместо ручного changelog.
- `Test_Results.md` — показательные доказательства вместо копирования результатов в статус.
- ADR — только важные решения и их причины.
- `Current_Stage.md` временно остаётся compatibility page и затем удаляется после очистки ссылок.

## Последствия

Количество обязательных правок после обычного изменения уменьшается. История не теряется: она разделяется между Git, ADR и test evidence. Связей становится меньше, но каждая ссылка ведёт к каноническому источнику.
