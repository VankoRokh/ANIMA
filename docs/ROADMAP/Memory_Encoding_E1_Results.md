## 1. Что проверено

Двадцать синтетических `conversation.user` Events через действующий `MemoryProcessor` (с Composer 64 и 512 chars) и независимый `ShadowEpisodeEncoder`. Референсные `gold` группы назначены до вычисления алгоритмов. Тестируются разные сущности CPU, сеть, межсессионные одинаковые тексты, интерливинг, формат пунктуации, noise и независимые темы. Никаких production migrations и writes из shadow.

CI: **86 профильных PASS / 1513 полных PASS** на каждой из трёх версий Python; `scripts/check.sh` и Core import — PASS. Лаборатория записала raw решения и пары ошибок.

## 3. Объяснение ошибок (по raw)

- Legacy объединяет два независимых наблюдения **CPU B и CPU C** (у разных `Entity ID`, но с почти идентичными словами и той же сессией).
- Legacy присоединяет к той же Memory отдельное событие о **CPU scheduling/inventory**, у которого общая сущность, но иная тема.
- Legacy объединяет два одинаковых сообщения о **Database checkpoint** из разных сессий.

Именно эти сценарии дали 10 ошибочных пар. Shadow применяет отрицательные границы `session_id`, раздельные валидированные `Entity ID` и минимум два значимых токена до объединения. Это объясняет выигрыш на E1, **не доказывает превосходство универсального алгоритма**.

## 4. Важное ограничение результата

В E1 Legacy с бюджетом 64 и с бюджетом 512 получил **одинаковые группировки**, несмотря на разный текст итоговой Memory. Следовательно, E1 **не доказал**, что компрессия вызвала увиденные ошибки. Он показывает преимущество явных границ над legacy score. Перенос этого результата на реальные логи без расширенного корпуса был бы методологической ошибкой.

**Дополнительный adversarial probe:** в последующей итерации лаборатории добавлен трёхсобытийный случай, специально различающий `Legacy-64` и `Legacy-512`: новая high-priority сводка может вытеснить ранний сырой маркер, изменив следующее ассоциативное решение. Также проверяется обратная цена shadow: **semantic/Entity-only continuation без общего текста может разорваться**, если нет авторизованного более сильного сигнала. Этот новый probe **не входит** в приведённую таблицу E1 и не считается verified, пока новый CI не пройдёт.

## 5. Вердикт и дальнейшая работа

**E1 functional lab — PASS** на подтверждённом SHA, `Stage 3 Memory Encoding` целиком **OPEN**. Стабильная production Memory не менялась. До переключения маршрута необходимы: независимые adversarial/мультиязычные эпизоды, анализ ложных разделений, датасет с длинными episode chains и реальная resource/replay дисциплина. Правило приоритета: **консервативный новый эпизод лучше необоснованного merge**, но полезные продолжения без лексического пересечения должны быть обнаружимы как `unknown/potential_related`, а не молчаливо потеряны.
