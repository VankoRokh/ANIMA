# Virtual ANIMA Lab — состояние полигона и результаты

**Статус:** P5-C и интерфейс Normal/Debug приняты владельцем как **завершённые изолированные испытания**. **ANIMA Core не подключён.** Полный исследовательский журнал и ранние P5-A/P5-B спецификации находятся в [истории](../ARCHIVE/Development_Snapshots.md).

## Назначение и границы

Godot управляет состоянием небольшого 2D-мира, Python — отдельным актором ANIMA, пользователь — Human с клавиатуры. Доступны карты `base`, `detour`, `clutter`; оператор может менять дверь, временные препятствия и добавлять шумовые события.

- Протоколы `val.bridge/0.1` и `val.bridge/0.2` используются **только для локальных тестов**. Поле `role` не аутентифицировано.
- Истина мира доступна оператору, наблюдение агента ограничено радиусом и версией. Невидимое не считается отсутствующим.
- Для `act` требуются `operation_id` и ожидаемые `epoch/revision`. Повтор в рамках живого процесса не должен выполнять эффект вторично; после аварии гарантии exactly-once нет.
- `Receipt` описывает итог команды, но **не подтверждает Goal**. Будущий Core должен самостоятельно получить проверяемое наблюдение.
- Шумовые события меняют журнал/логическое время, но не ревизию физического мира; пока ANIMA не классифицирует их самостоятельно.
- F3 переключает **Normal/Debug** без изменения состояния мира и прав доступа. Отладочное окно показывает данные оператору, а не агенту.

Полная Python-регрессия **1450/1450 PASS** на чистом `e995169e61385a3e1c2e44a60b27e6bf501211e2`; владелец подтвердил нативные тесты, повторные P5-A/B smoke, визуальные карты и работу F3/ярлыка. Исходные отдельные консольные логи не все приложены; независимого аудита Lab не было.

Проверяемые команды:

```bash
bash scripts/check.sh
.venv/bin/python -m pytest -q
GODOT_BIN="$HOME/.local/opt/godot/Godot_v4.7.2-stable_linux.x86_64"
"$GODOT_BIN" --headless --path labs/virtual_anima_lab/godot --script res://BridgeV2ContractTest.gd
"$GODOT_BIN" --headless --path labs/virtual_anima_lab/godot --script res://BridgeP5CScenarioTest.gd
"$GODOT_BIN" --headless --path labs/virtual_anima_lab/godot --script res://BridgeUiModeTest.gd
.venv/bin/python labs/virtual_anima_lab/python/scenario_runner.py --godot "$GODOT_BIN" --report-dir "$(mktemp -d)"
```

Обычный запуск в Ubuntu: `bash labs/virtual_anima_lab/install_desktop_launcher.sh`, затем `gtk-launch virtual-anima-lab`. Внутри окна F3 включает диагностику.

## Перед интеграцией с Core (P6)

Сначала завершить повторный независимый аудит Core v0.1. Затем спроектировать **доверенный адаптер**: реальная регистрация источников, идентичность получателя/исполнителя, политика действий, отдельные времена наблюдения и получения, обработка неопределённых эффектов, независимая Verification. Не включать демонстрационный TCP-bridge напрямую в системный Executor.

См. [границы ревизии Core](Core_v0_1_Audit_Boundaries.md), [план Core/VAL](Core_v0_1_VAL_v0_1_Plan_Draft.md). Инструкция по запуску лаборатории — `labs/virtual_anima_lab/README.md` (путь к исходному файлу; тестовые документационные снимки не копируют `labs/`).
