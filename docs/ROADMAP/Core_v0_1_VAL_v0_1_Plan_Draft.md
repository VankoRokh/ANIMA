## Обязательные свойства перед интеграцией

1. Core получает наблюдения только от **зарегистрированного доверенного адаптера**, а не из самозаявленного `role` TCP-клиента.
2. Версия/время наблюдения, время доставки и область действия источника сохраняются отдельно; `absence != false`.
3. Core остаётся владельцем Goals/Tasks, Policy, планировщика, Journal, состояния и проверки. Godot не завершает системные цели напрямую.
4. Перед каждым действием повторно проверяются разрешение, текущие preconditions, идентичность операции и её бюджет.
5. `Receipt` не служит подтверждением успеха Goal: необходимо новое независимое наблюдение и проверка утверждённых условий.
6. При потере ответа или перезапуске внешней среды Core **не повторяет эффект вслепую**; сначала сверяет состояние и ранее известный operation ID.
7. Ограничения ресурсов, конфликтующие задачи, шум, блокировка и отсутствие необходимых способностей дают объяснимый отказ или отложенное решение.

## Порядок P6

| Шаг | Проверяемый выход |
|---|---|
| 1. Независимый повторный аудит Core | Подтверждённые инварианты, точный чистый SHA, отрицательные тесты и явные нерешённые риски. |
| 2. Версия доверенного адаптера | Типизированные observations/capabilities, идентичность источника/актора, ошибки, временные области и лимиты. |
| 3. Первый сценарий без LLM | Core обнаруживает состояние двери, предлагает действие, проверяет допуск, исполняет и независимо подтверждает результат. |
| 4. Отрицательные случаи | Старая ревизия, вмешательство Human, блокировка, отсутствие объекта в поле зрения, повтор и пропавший ответ. |
| 5. Recovery/trace | Перезапуск, сохранение операции, реконструкция причинных связей и отсутствие двойного эффекта в поддерживаемых fault classes. |
| 6. Регрессия | P5-A/B/C, нативные Godot-тесты, полный Python-suite, проверки документации, точный SHA и отчёт. |

**Граница P6:** одинаковые классы сценариев должны проходить через in-process тестовый адаптер и через Lab при сопоставимых наблюдениях; отказ камеры, отсутствие Human или LLM не должны разрушать базовый Core. Модель, навигация и графика подключаются как возможности, а не как отдельные владельцы решений.
