# ANIMA v0.2 — E2.5c-M: проверка пользы памяти и пересмотра устаревших представлений

**Вердикт:** `PASS_LAB_PAIRED_MEMORY_CONFLICT` — узкая исследовательская проверка поведенческого эффекта памяти в Godot. Это **не** переход к LLM, не полноценный пространственный World Model и **не** native Stage6 action admission.  
**Дата:** 24 ноября 2026.  
**Первый полностью проверенный snapshot кода:** `2d5dec76b7d6b0912ee76cdb4c80cafa3805dc41`.  
**Первичный evidence:** [GitHub Actions #45377821149](https://github.com/VankoRokh/ANIMA/actions/runs/45377821149), **4/4 SUCCESS**, Python 3.12/3.13/3.14 — **2493 PASS** на каждой версии, реальный официальный Godot 4.7.2, seed 7 и 8. Архив `anima-e25c-memory-evidence` включает `e25c-results.json`, журналы Godot, Core и лабораторные испытания.  
**База:** [E2.5b Visual Decision Runner](e2-5b-visual-decision-lab-acceptance-v02.md), [E2.4a память](e2-4-working-memory-acceptance-v02.md), [E2.4b относительная одометрия](e2-4b-relative-pose-acceptance-v02.md).

## 1. Научный вопрос

Меняется ли **фактический выбор действий** при доступе к ранее полученным наблюдениям? Что происходит, если информация в памяти перестаёт соответствовать текущему миру?

Критерии отличаются от прежнего E2.5b, который подтверждал только сам замкнутый цикл. Здесь используется **парный эксперимент**, в котором один и тот же seed, начальный мир и подготовленная история подаются детерминированной политике в двух условиях: `memory_enabled=True/False`.

Важно: memory-off **не** удаляет Raw/корневую память — только запрещает использование исторических сенсорных записей при принятии очередного решения. Прошлая история подготовлена внешним доверенным harness **до** начала оцениваемых самостоятельных действий. Эта prehistory исключается из итогового числа `policy_actions`.

## 2. Экспериментальные сценарии

### FAMILIAR — прошлое наблюдение остаётся верным

1. На старте ANIMA направлена на север и не видит ящик.
2. Harness совершает два подтверждённых поворота вправо; ANIMA видит ящик на востоке и затем смотрит на юг.
3. Оцениваемая политика самостоятельно выбирает следующие действия. Цель — повторно обнаружить ящик и выполнить один подтверждённый шаг в его направлении.

**Memory on:** память и история локальных движений позволяют выбрать **левый поворот** к знакомому объекту.  
**Memory off:** детерминированный поиск идёт вправо и обходит направления до повторного обнаружения объекта.

### RELOCATED — старое положение объекта перестало быть актуальным

Исходная сенсорная история и повороты **такие же**, что в FAMILIAR. После этого доверенный Godot-оператор, пока объект вне поля зрения агента, перемещает ящик на противоположную сторону. В модель ANIMA передаётся **только следующее типизированное наблюдение**; истинные координаты оператора не проходят в агентский Context или в DecisionRecord.

- Godot `--lifecycle-e25c-fixtures` включает отдельную **opt-in operator-only** команду `relocate_item` с ограниченным форматом, epoch, expected sample/revision и идемпотентным fixture ID.
- Операторская квитанция без координат записывается в E2.4b `e24b_external_changes` и сопоставляется с новым Core-backed Raw по revision/tick.
- Внешнее изменение **не** обновляет положение самой ANIMA: локальная pose остаётся прежней. Неожиданные несогласованные clock transitions по-прежнему fail-closed.
- При повторной проверке прежнего направления ANIMA **не видит** ящик. Это фиксируется как `SUSPECTED_STALE`, привязанное к `prior_event_id` и `suspected_event_id`, **не** как подтверждённое `object_absent`.
- После нового прямого наблюдения предмета статус меняется на `REOBSERVED_AFTER_CONFLICT`. Оригинальный Raw остаётся неизменным; исправляется **гипотеза о текущем положении**, а не ретроспективный факт старого наблюдения.
- Видимая непрозрачная преграда перед ожидаемой позицией препятствует преждевременной диагностике противоречия.

## 3. Результаты

| Seed | Сценарий | Memory ON | Memory OFF | Вывод |
| --- | --- | ---: | ---: | --- |
| 7 | FAMILIAR | **2 действия** | 4 действия | Актуальная память сократила поиск |
| 8 | FAMILIAR | **2 действия** | 4 действия | Результат воспроизведён |
| 7 | RELOCATED | **4 действия** | 2 действия | Устаревшая память вызвала лишний поиск, затем гипотеза была пересмотрена |
| 8 | RELOCATED | **4 действия** | 2 действия | Результат воспроизведён |

В каждом прогоне лабораторная цель `COMPLETED_LAB_CONDITION` достигнута после проверенного forward step. Это **не** полная доставка предмета и не метрика долгосрочной автономной эффективности.

**Последовательности причин:**

- FAMILIAR ON: `CHECK_REMEMBERED_TARGET → APPROACH_VISIBLE_CRATE`.
- FAMILIAR OFF: `SEARCH_NEW_VIEW ×3 → APPROACH_VISIBLE_CRATE`.
- RELOCATED ON: `CHECK_REMEMBERED_TARGET → PRIOR_LOCATION_NOT_REOBSERVED → SEARCH_AFTER_MEMORY_CONFLICT → APPROACH_VISIBLE_CRATE`.
- RELOCATED OFF: `SEARCH_NEW_VIEW → APPROACH_VISIBLE_CRATE`.

В режиме RELOCATED ON, например, второе решение создаёт не вывод `object_gone`, а слабый evidence-linked признак несовместимости старого пространственного предположения с новым обзором. Дальнейшее решение перестаёт использовать эту геометрию как актуальную.

**Чего данные НЕ доказывают:** увеличение количества действий в RELOCATED не является измерением «общего вреда памяти» — это результат специально выбранной геометрии, фиксированной политики и заданной альтернативы поиска. Две разные seeded obstacle configurations используют один и тот же центральный сюжет. Не подтверждены статистическая обобщаемость, адаптивное обучение, реальная локальная LLM или выбор собственных глобальных целей.

## 4. Проверки целостности и границ

- Неподдельность старых исходных данных в смысле E2.4a: каждый Raw проверяется по SHA-256, Core event и forwarded receipt; рабочая проекция проверяется против Raw.
- E2.4b: каждый исходный тестовый поворот и последующий ход агента сопоставляются с полным Godot action ledger и следующим Core-backed наблюдением.
- Внешняя перестановка не считается `actor_movement`; fixture receipt хранит `before_sample_id`, `event_id`, revision/tick и не содержит операторских координат.
- Строгий operator-only доступ; отдельный негативный live-тест проверяет невозможность вызвать `relocate_item` через agent executor credential.
- `visual_hypotheses` хранит ссылки на старое, несовпадающее и новое подтверждённое наблюдение; отсутствие в текущем обзоре **не** автоматически становится подтверждённым Knowledge.
- Нет разрешённых слепых шагов к историческим координатам; перед подходом ящик должен быть виден в текущем Raw.
- Сохраняются жёсткие бюджеты действий, остановка при неопределённости и лабораторная запись admission **до** эффекта / outcome **после** proof.
- Полная регрессия E1.2–E2.5b и Python 3.12–3.14.

**Открытые риски:** Godot fixture — доверенный лабораторный инструмент, не производственный сенсор; sidecar SQLite и canonical Core не имеют единой транзакции/backup; same-UID actor может атаковать локальные токены; длинные маршруты, обновление Memory/Knowledge и per-episode learning не реализованы; hypothesis resolution основан на эвристической пороговой проверке, а не на вероятностной пространственной модели. Это всё ещё **`LAB_ADMISSION`**, не нативный Core Goal/Task/Execution/Verification.

## 5. Запуск на ноутбуке с визуализацией

Из отдельного checkout этой экспериментальной ветки:

```bash
# Наблюдаем пользу памяти:
bash scripts/run_visual_decision_lab.sh --scenario familiar --memory on --seed 7
bash scripts/run_visual_decision_lab.sh --scenario familiar --memory off --seed 7

# Наблюдаем устаревшее положение и его пересмотр:
bash scripts/run_visual_decision_lab.sh --scenario relocated --memory on --seed 7
bash scripts/run_visual_decision_lab.sh --scenario relocated --memory off --seed 7
```

Каждая команда создаёт **новый временный Core** и запускает графический Godot. Закрыть предыдущий экземпляр перед следующим запуском. После появления интерфейса нажать RUN; для детальной проверки можно несколько раз нажимать STEP. В правой панели показываются `Trial`, `Memory`, выбор действия, `MEMORY HYPOTHESES (not Knowledge)` и доказательные ссылки. В операторской части сцены видно истинное положение предмета **только для человека**. Не использовать скриншот с операторским HUD как сенсор для FAST.

Для автоматического воспроизведения:

```bash
bash scripts/run_e25c_memory_gate.sh /path/to/Godot_v4.7.2-stable_linux.x86_64
```
