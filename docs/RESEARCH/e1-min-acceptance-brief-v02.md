# ANIMA v0.2 — независимый E1-min gate: критерии до испытаний

**Тип:** исследовательская приёмка лабораторного `E1-min`; **не** release gate, не E2 и не подтверждение самостоятельной деятельности ANIMA.  
**Дата фиксации:** 23 ноября 2026.  
**Baseline (не изменять):** `3a922429aa00e439495346c140048e484c867cb4` — E1.1–E1.4, Godot и Python-контракты.  
**Аудиторская ветка:** `audit/v02-e1min-independent-acceptance`. Здесь разрешены только тесты, отчёты и проверочный CI; изменения `anima/` и `labs/virtual_anima_lab/godot/LifecycleWorld.gd` запрещены.  
**Предыдущее evidence:** [E1.4 CI 45164978286](https://github.com/VankoRokh/ANIMA/actions/runs/45164978286), 2356 PASS × Python 3.12/3.13/3.14 и Godot 4.7.2 live PASS.

## Предмет

Проверить, что **вместе**, а не изолированно, работают E1.1 (строгие DTO), E1.2 (наблюдательный мир с двумя обходами), E1.3 (три виртуальных действия + новый sensor readback), E1.4 (ограниченный журнал, повтор без нового эффекта, status/reconcile). Агентский Core, FAST, Memory и Knowledge **не подключаются**. Маршруты выбирает исключительно независимый test harness, а не «автономная ANIMA».

## Обязательные критерии

| ID | Требование PASS | Как проверить независимо |
| --- | --- | --- |
| IM-01 | `observe-only` не имеет effects; `effects-only` не имеет ledger; E1.4 — только явный opt-in | Три разных живых процесса; `hello.capabilities` и отрицательные команды |
| IM-02 | Agent не получает hidden `inspect`, seed, remote zone или операторские команды | Реальные TCP-запросы; `FORBIDDEN`; проверка DTO первого observation |
| IM-03 | Обход верхом и низом физически работает на реальном Godot; предмет попадает в delivery | Seed 7/8 × top/bottom; для каждого шага `WorldAction → receipt → fresh WorldObservation → proof` |
| IM-04 | Перекрытый прямой путь честно выдаёт `BLOCKED`, а не false success | Попытка `world.move E` из `(5,5)`; `VERIFIED_BLOCKED` и отсутствие эффекта |
| IM-05 | После **реального** отправленного TCP-action без чтения ответа статус позволяет восстановить оригинальный receipt | Уничтожить клиентское TCP-подключение после send, затем reconnect → `RECORDED` + независимый новый sensor proof |
| IM-06 | Повтор той же операции не создаёт вторых `revision/tick/event_seq`; чужие параметры и status-query с тем же ID отклоняются | Replay и `OPERATION_CONFLICT`; проверка readback и clock |
| IM-07 | Изменение среды оператором делает старое наблюдение недопустимым | `set_obstacle` повышает revision; stale action отклоняется, `operation_status=UNKNOWN`, нет implicit retry |
| IM-08 | Receipt/status нельзя самостоятельно превратить в `VERIFIED_SUCCESS` | Подделать owner в readback, запретить `replayed=true` как proof, проверить отрицательные состояния |
| IM-09 | Reset и process restart не создают ложной непрерывности/прав на старый action | Reset → новая epoch, старый status `UNKNOWN`, action запрещён; новый process ID после restart, старый action `WORLD_CHANGED` |
| IM-10 | Переполнение bounded 256-entry journal не вытесняет доказательства и не открывает новые действия | Независимый E1.4 native/live regression + специальный E1-min capacity probe, если потребуется |
| IM-11 | Python DTO/полная регрессия/старый P5/P6/M2 не деградировали | Python 3.12/3.13/3.14 и официальный Godot 4.7.2; чистая проверка docs |
| IM-12 | Аудитор не исправляет реализацию во время измерения и публикует отрицательные результаты | Изменённые файлы ограничены test/docs/CI, исходные ошибки сохранены в Actions |

**Строгая интерпретация:** любой дефект исполнения, пропуск проверки идентификатора, ложный `VERIFIED_SUCCESS`, дублирование эффекта или регрессия базового мира — `FAIL/BLOCKED` до отдельного remediation и полного re-audit. Сбой инфраструктуры без данных — `INCONCLUSIVE`, не PASS. Число успешных тестов само по себе не заменяет проверку критериев.

## Ограниченный доверенный профиль

1. Лабораторная сцена слушает только `127.0.0.1`, но `role=agent/operator` — **самообъявленное** поле. Изоляция и запрет операторских команд проверяются только для добросовестно подключённого агента. Наличие доверенной аутентификации **не утверждается**. E2 не вправе выдавать этот raw port модели или произвольному процессу: нужен отдельный доверенный admission/adapter.
2. Ledger хранится в памяти живого Godot-процесса и **не** переживает restart. E1-min не подменяет E4 durability/restore и не доказывает exactly-once между различными процессами.
3. `RECORDED` подтверждает утверждение мира о receipt; его достоверность не равна независимому proof. `UNKNOWN` запрещает безусловную переотправку.
4. Заданный harness маршрут — **не** доказательство когнитивного выбора, планирования, устойчивой памяти или реальной автономности.
5. E1-min не включает энергию, станции зарядки, семантическое обучение или реальные FAST/DEEP; они остаются будущими расширениями основного E1/E2–E6.

## Воспроизведение и отчёт

Предусмотрен `tests/e1_min_independent_live_audit.py` и CI `.github/workflows/anima-e1min-independent-acceptance.yml`. CI должен сохранить полный stdout, исходные Godot logs, результаты регрессии, сведения об окружении и точный `git rev-parse HEAD`. Итоговый документ может объявить только один из `PASS_LAB_RESTRICTED`, `FAIL/BLOCKED` или `INCONCLUSIVE`, с явными открытыми ограничениями и без изменения релизного тега `v0.2.0-rc.1`.

**Запрещённое сокращение:** даже `PASS_LAB_RESTRICTED` не даёт автоматического разрешения объединить E1 ветки с release или начать E2 без review архитектурных полномочий.
