# ANIMA — контекст для ИИ-помощника

ANIMA — модульный агент с переносимым состоянием/опытом, будущим разделением Fast/Deep и перспективой физического воплощения. Документация и объяснения ведутся на русском; имена файлов и идентификаторы — латиницей.

## Перед работой

Прочитать:

1. [Project Status](Project_Status.md);
2. [Roadmap](../06_ROADMAP/Roadmap.md);
3. описание нужного модуля через [Module Index](Module_Index.md);
4. код этого модуля;
5. связанные ADR только если задача затрагивает принятое решение.

Не требуется автоматически перечитывать весь vault.

## Правила достоверности

- текущий статус берётся только из `Project_Status.md`;
- фактическое поведение проверяется кодом и тестом;
- Accepted ADR фиксирует принятое решение, но не означает готовую реализацию;
- Draft/Experiment не считать утверждённым поведением;
- память чата помогает восстановить обсуждение, но не переопределяет репозиторий.

## Разработка

Работать небольшими проверяемыми шагами. Перед кодом понимать, **какое свойство системы должно измениться и как это будет проверено**.

После изменения обновлять только канонический документ, которому действительно принадлежит изменившийся факт. Обычные успешные прогоны не превращать в документацию.

Правила: [Documentation Rules](../09_OPERATIONS/Documentation_Rules.md). Тесты: [Test Strategy](../07_EXPERIMENTS/Test_Strategy.md).

## Данные экземпляра

Пользовательские данные локальны. По умолчанию используется `<project>/data`, либо `ANIMA_DATA_DIR`. Не использовать реальные данные экземпляра в тестах без необходимости; проверки должны предпочитать временные синтетические данные.

## Текущий приоритет

Stage 0 закрыт. Перед Stage 1 проводится ревизия roadmap, критериев этапов, тестовой системы и наблюдаемости. Полноценный GUI отладки пока не является обязательной задачей; сначала нужен стабильный диагностический слой.
