# Фундамент: идентичность, события и среда исполнения

**Статус:** механизмы реализованы. Базовый v0.1 использует их через `build_core` и `Runtime`; старый интерактивный CLI остаётся отдельным совместимым интерфейсом.

## Задача слоя

Сохранить **один экземпляр ANIMA** при завершении и возобновлении процесса; отделить данные экземпляра от кода и независимых когнитивных backend.

```text
Оператор / адаптер
       ↓
 Runtime — управляет жизненным циклом
       ├─ Identity: постоянный instance_id
       ├─ AnimaState: статус и сессии
       ├─ EventBus: очередь событий процесса
       ├─ EventLog: исходные Events
       └─ EventProcessingCoordinator → Memory
```

## Основные компоненты

| Компонент | Роль | Реализация |
| --- | --- | --- |
| `Identity` | `instance_id`, отделённый от сессии | [identity.py](../../anima/core/identity.py) |
| `AnimaState` | `created/awake/sleeping`, session и счётчики | [state.py](../../anima/core/state.py) |
| `EventBus` | временная доставка событий внутри процесса | [event_bus.py](../../anima/core/event_bus.py) |
| `EventLog` | первичная долговечная история | [event_log.py](../../anima/memory/event_log.py) |
| `EventProcessingCoordinator` | фиксация состояния обработки, восстановление | [event_processing.py](../../anima/memory/event_processing.py) |
| `Runtime` | wake, user input, sleep и координация служб | [runtime.py](../../anima/runtime.py) |
| `build_core` | единственная composition root с явными опциональными модулями | [assembly.py](../../anima/core/assembly.py) |

У типизированного Core есть **отдельный** контур принятия зарегистрированных наблюдений (`CoreIngress`/Belief), который не следует путать с произвольным `conversation.user`. В обычном профиле v0.1 источники typed Belief пусты. [Подробнее о полномочиях](Execution_and_Verification.md).

## Жизненный цикл и данные

`Runtime.wake()` восстанавливает обработку, переводит State в активный режим и фиксирует `system.wake`. Затем `user_input()` формирует raw Event с источником `user` и передаёт его на обработку. `Runtime.sleep()` фиксирует системный `system.sleep` и переход состояния.

Долговременные `identity.json`, `state.json`, `events.jsonl`, `memory.db` находятся в экземпляре. Смена программы **не должна** сама менять идентичность. При переносе нужно резервировать данные **всего** экземпляра после безопасной остановки, а не только одну SQLite-базу.

`anima.release_v01` добавляет последовательные JSON-команды и кооперативную одноэкземплярную блокировку Linux; это не отдельный Core. Не допускается скрытое переоткрытие данных другого профиля полномочий.

## Границы

- Очередь `EventBus` — не заменитель долговечного журнала.
- Событие о чьём-то утверждении — не независимое измерение мира.
- Команда, не подтвердившая запись, может не пережить аварийное завершение.
- `flock` защищает только от второго штатного процесса, а не от недоверенного локального кода.
- Перенос Identity и копии данных не доказывает субъективного сознания.
