# Память

Сырой журнал фиксирует все обработанные события; MemoryFilter создаёт отобранные записи; MemoryStore сохраняет их отдельно. EpisodicMemory читает выбранные воспоминания из memories.jsonl. Это базовый слой долговременной эпизодической памяти, но ещё не полноценная когнитивная память.

## MEM-01

**Сырой журнал EventLog.** Решение: **Accepted**. Реализация: **Prototype**.

- **Назначение:** Сохранять каждое обработанное событие для последующей проверки.
- **Входы:** Event в write(event).
- **Выходы:** Одна JSON-строка в data/events.jsonl на событие.
- **Зависимости:** Event.to_dict(), json, pathlib, файловая система.
- **Код:** [EventLog](../../anima/memory/event_log.py).
- **Сейчас:** Дописывает wake, user_input и sleep; создаёт родительскую папку.
- **Следующее:** Рассмотреть IDs, проверку записи и восстановление повреждённой последней строки.
- **Проблемы:** Нет ротации, транзакции с state.json и режима нескольких писателей.
- **Проверка:** Полный цикл создаёт три строки; повторный запуск добавляет историю.
## MEM-02

**Фильтр MemoryFilter.** Решение: **Accepted**. Реализация: **Prototype**.

- **Назначение:** Отделять выбранный ввод от служебных событий.
- **Входы:** Event с event_type=user_input и payload.text.
- **Выходы:** is_meaningful() — bool; create_memory() — source, timestamp, content.
- **Зависимости:** Согласованный формат пользовательского события.
- **Код:** [MemoryFilter](../../anima/memory/filter.py).
- **Сейчас:** Пропускает любой непустой текст после strip(); сохраняет исходный payload без удаления пробелов.
- **Следующее:** Добавить валидацию и исследовать оценку важности.
- **Проблемы:** Название is_meaningful не означает смыслового анализа. Неверный тип payload/text может вызвать ошибку.
- **Проверка:** Служебные события и пустой ввод не становятся выбранными воспоминаниями.
## MEM-03

**Хранилище MemoryStore.** Решение: **Accepted**. Реализация: **Prototype**.

- **Назначение:** Сохранять сформированные воспоминания.
- **Входы:** Словарь из create_memory().
- **Выходы:** JSONL-запись в data/memories.jsonl.
- **Зависимости:** MemoryFilter, json, pathlib, файловая система.
- **Код:** [MemoryStore](../../anima/memory/memory_store.py).
- **Сейчас:** Дописывает записи в memories.jsonl; чтение выбранной памяти выполняет отдельный EpisodicMemory.
- **Следующее:** Добавить метаданные, идентификаторы и более явную связь с исходными событиями.
- **Проблемы:** Нет ID, версии схемы, связи с исходным событием или контроля дубликатов.
- **Проверка:** После повторного запуска старые выбранные записи остаются доступными.
## MEM-04

**Чтение EpisodicMemory.** Решение: **Accepted**. Реализация: **Prototype**.

- **Назначение:** Читать выбранную эпизодическую память и предоставлять последние сохранённые записи.
- **Входы:** memory_file; запросы load_memories(), count(), last(limit=5).
- **Выходы:** Список выбранных воспоминаний, количество и последние элементы.
- **Зависимости:** Формат memories.jsonl: source, timestamp, content.
- **Код:** [EpisodicMemory](../../anima/memory/episodic.py).
- **Сейчас:** Читает data/memories.jsonl. Пустой или отсутствующий файл даёт пустой список. В main.py вызываются count() и last(3).
- **Следующее:** Добавить валидацию записей, IDs и более эффективное чтение при росте файла.
- **Проблемы:** Повреждённая JSON-строка вызывает исключение; весь файл загружается в память.
- **Проверка:** Непустой ввод сохраняется и отображается после повторного запуска; пустой ввод не увеличивает число выбранных воспоминаний. SW-01 завершена в commit 2fff48d.
## MEM-05

**Рабочая память и контекст.** Решение: **Draft**. Реализация: **Planned**.

- **Назначение:** Держать ограниченный текущий контекст для обработки задачи.
- **Входы:** Проектно: активная задача, последние события и извлечённые записи.
- **Выходы:** Контекст для Fast/Deep с указанием источников.
- **Зависимости:** Извлечение памяти, модели, бюджет токенов/оперативной памяти.
- **Сейчас:** Отдельного модуля нет; список последних событий в CLI его не заменяет.
- **Следующее:** Определить срок жизни и правила вытеснения.
- **Проблемы:** Нельзя смешивать текущую гипотезу и подтверждённую долговременную запись.
- **Проверка:** Контекст ограничен ресурсами и воспроизводимо собирается из известных источников.
## MEM-06

**Семантическая память.** Решение: **Draft**. Реализация: **Planned**.

- **Назначение:** Хранить выводы и знания, полученные из опыта.
- **Входы:** Проектно: эпизоды, результат анализа и подтверждения.
- **Выходы:** Утверждения со ссылками на исходные записи и статусом достоверности.
- **Зависимости:** Deep/консолидация, схема источников и версии записи.
- **Сейчас:** Не реализована.
- **Следующее:** Определить минимальную схему факта, гипотезы и исправления.
- **Проблемы:** Сжатие не должно превращать предположение модели в достоверный факт.
- **Проверка:** Каждый вывод имеет источник; противоречивые сведения не теряются.
## MEM-07

**Извлечение памяти.** Решение: **Draft**. Реализация: **Planned**.

- **Назначение:** Находить записи, относящиеся к текущей задаче.
- **Входы:** Проектно: запрос, фильтры, ограничение числа результатов.
- **Выходы:** Упорядоченные записи с IDs и объяснимой причиной отбора.
- **Зависимости:** Хранилище, индексы и формат контекста.
- **Сейчас:** Есть только последние сырые события; тематического поиска нет.
- **Следующее:** Начать с простого проверяемого поиска; необходимость embeddings определить измерением.
- **Проблемы:** Релевантность и эмоциональная важность различаются.
- **Проверка:** Извлечение возвращает известные релевантные примеры, сохраняет источники и укладывается в бюджет.
## MEM-08

**Оценка важности.** Решение: **Experiment**. Реализация: **Planned**.

- **Назначение:** Проверить, помогает ли ранжирование сохранять полезный опыт.
- **Входы:** Проектно: событие, контекст, повторение и внутренние оценки.
- **Выходы:** Проектно: score с факторами и причиной сохранения.
- **Зависимости:** Корпус примеров, критерии полезности и журнал исходных событий.
- **Сейчас:** MemoryFilter применяет только проверку непустого ввода.
- **Следующее:** [EXP-001](../07_EXPERIMENTS/README.md#exp-001) сравнивает простой отбор и вариант с эмоциональным весом.
- **Проблемы:** Сильная реакция не доказывает истинность или пользу записи; веса ещё не утверждены.
- **Проверка:** Заранее выбранные метрики качества и объёма памяти сравниваются на одинаковом наборе.
## MEM-09

**Забывание и сжатие.** Решение: **Draft**. Реализация: **Planned**.

- **Назначение:** Управлять ростом памяти и стоимостью обработки.
- **Входы:** Проектно: возраст, обращения, значимость и ограничения объёма.
- **Выходы:** Проектно: архив, обобщение или явная пометка для удаления.
- **Зависимости:** Политика хранения, резервирование и семантическая память.
- **Сейчас:** Все журналы растут без ограничения.
- **Следующее:** Определить границы между архивом, сжатием и удалением.
- **Проблемы:** Удаление исходников может сделать невозможной проверку происхождения вывода.
- **Проверка:** Результат измеряется по качеству поиска и объёму; необратимые операции имеют проверенный путь восстановления.
