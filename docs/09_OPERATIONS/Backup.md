# Резервирование

Код и документация восстанавливаются из Git. Опыт экземпляра восстанавливается только из отдельной копии data. Само исключение из Git резервную копию не создаёт.

## Что сохранять

| Сейчас | Почему |
|---|---|
| `<data-dir>/state.json` | Сессии, счётчики и состояние |
| `<data-dir>/identity.json` | Постоянный instance_id и минимальная схема идентичности |
| `<data-dir>/events.jsonl` | Сырой опыт |
| `<data-dir>/memories.jsonl` | Отобранные записи |
| SHA commit | Версия кода, соответствующая данным |
| Версия Python | Воспроизведение окружения |

В будущем добавятся версии моделей, расширенная конфигурация и новые схемы данных. Секреты резервируются отдельно и не публикуются. .venv не переносится.

## Когда

После значимых сессий и перед изменением схемы/переносом. Точный график и место независимой копии ещё не настроены; это задача проекта.

## Текущая ручная процедура

Ниже описана проверенная процедура для каталога по умолчанию `<project>/data`. Если используется `ANIMA_DATA_DIR`, не подменять путь вручную без проверки: перенос внешнего каталога входит в ближайшую контрольную задачу Stage 0.

Сначала завершить ANIMA штатно и убедиться, что процесс остановлен. Из корня проекта создать архив:

```bash
task_backup_dir="$HOME/ANIMA-backups"
task_backup_stamp="$(date +%Y%m%d-%H%M%S)"
task_backup_file="$task_backup_dir/ANIMA-$task_backup_stamp.tar.gz"
mkdir -p -- "$task_backup_dir"
git rev-parse HEAD > "$task_backup_file.commit"
python3 --version > "$task_backup_file.python"
tar -czf "$task_backup_file" data
(
    cd -- "$task_backup_dir"
    sha256sum "ANIMA-$task_backup_stamp.tar.gz" > "ANIMA-$task_backup_stamp.tar.gz.sha256"
)
```

Если data отсутствует, экземпляр ещё не создан либо используется другой путь; не считать такой архив успешным.

Архив и три соседних файла нужно скопировать на независимый носитель или выбранное приватное хранилище. Копия на том же ноутбуке не покрывает его потерю. Реальные данные не отправляются в публичный GitHub.

## Проверка копии

В папке копии выполнить sha256sum -c для соответствующего .sha256, затем просмотреть архив через tar -tzf. Он должен содержать только ожидаемые data/ файлы.

После этого восстановить в новой рабочей папке по [Recovery](Recovery.md). Проверить сессии и историю до запуска. Успех архиватора и проверка суммы подтверждают целостность файла; практический запуск подтверждает возможность восстановления.

## Ограничения

При работающей ANIMA разные файлы могут попасть в архив в разные моменты; поэтому текущая процедура выполняется после остановки. Шифрование, ротация и автоматическое расписание пока не настроены.
