# Резервирование

Код и документация восстанавливаются из Git. Опыт экземпляра восстанавливается только из отдельной копии data. Само исключение из Git резервную копию не создаёт.

## Что сохранять

| Сейчас | Почему |
|---|---|
| `<data-dir>/state.json` | Сессии, счётчики и состояние |
| `<data-dir>/identity.json` | Постоянный instance_id и минимальная схема идентичности |
| `<data-dir>/events.jsonl` | Сырой опыт |
| `<data-dir>/memories.jsonl` | Отобранные записи |
| SHA commit | Версия кода, соответствующая данным |
| Версия Python | Воспроизведение окружения |

В будущем добавятся версии моделей, расширенная конфигурация и новые схемы данных. Секреты резервируются отдельно и не публикуются. .venv не переносится.

## Когда

После значимых сессий и перед изменением схемы/переносом. Точный график и место независимой копии ещё не настроены; это задача проекта.

## Текущая ручная процедура

Процедура одинакова для стандартного `<project>/data` и внешнего `ANIMA_DATA_DIR`. Сначала завершить ANIMA штатно и убедиться, что процесс остановлен. Из корня проекта:

```bash
task_data_dir="$(python3 -c 'from anima.config.paths import get_data_dir; print(get_data_dir())')"
task_backup_dir="$HOME/ANIMA-backups"
task_backup_stamp="$(date +%Y%m%d-%H%M%S)"
task_backup_file="$task_backup_dir/ANIMA-$task_backup_stamp.tar.gz"

mkdir -p -- "$task_backup_dir"

for name in state.json identity.json events.jsonl memories.jsonl; do
    test -f "$task_data_dir/$name" || {
        echo "Missing instance file: $task_data_dir/$name" >&2
        exit 1
    }
done

git rev-parse HEAD > "$task_backup_file.commit"
python3 --version > "$task_backup_file.python"

tar -C "$task_data_dir" -czf "$task_backup_file" .

(
    cd -- "$task_backup_dir"
    sha256sum "$(basename "$task_backup_file")"         > "$(basename "$task_backup_file").sha256"
)
```

Архив содержит содержимое каталога экземпляра, а не его старый абсолютный путь. Поэтому одна и та же копия может быть восстановлена как стандартный `data/` или в новый внешний `ANIMA_DATA_DIR`.

Архив и три соседних файла нужно скопировать на независимый носитель или выбранное приватное хранилище. Копия на том же ноутбуке не покрывает его потерю. Реальные данные не отправляются в публичный GitHub.

## Проверка копии

В папке копии выполнить `sha256sum -c` для соответствующего `.sha256`, затем просмотреть архив через `tar -tzf`. Ожидаются только файлы экземпляра: `state.json`, `identity.json`, `events.jsonl`, `memories.jsonl` (tar может показывать их с префиксом `./`).

После этого восстановить в новой рабочей папке по [Recovery](Recovery.md). Проверить сессию, `instance_id` и историю до первого запуска. Успех архиватора и проверка суммы подтверждают целостность архива; практическое продолжение восстановленного экземпляра подтверждает возможность восстановления.

Эта процедура проверена вручную 2026-10-13 на внешнем `ANIMA_DATA_DIR`: восстановленная копия совпала с исходной побайтно и продолжила историю независимо от исходного каталога.

## Ограничения

При работающей ANIMA разные файлы могут попасть в архив в разные моменты; поэтому текущая процедура выполняется после остановки. Шифрование, ротация и автоматическое расписание пока не настроены.
