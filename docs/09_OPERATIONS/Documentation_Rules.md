# Правила документации

## Один проектный источник

docs хранится вместе с исходниками. Действующие ADR фиксируют принятые решения; код и проверки подтверждают реализацию. При расхождении описать оба состояния и задачу исправления.

Чат — источник обсуждения, но не замена закреплённой документации. Источником истины не становится произвольный непроверенный текст только потому, что он попал в Git.

## Статусы

| Ось | Статусы | Смысл |
|---|---|---|
| Решение модуля | Accepted / Draft / Experiment | Принятое направление / обсуждаемый дизайн / проверяемая гипотеза |
| Реализация модуля | Planned / Prototype / Implemented / Tested / Stable / Deprecated | Нет кода / ограниченный код / заявленные функции / целевые проверки / устойчивая эксплуатация / вывод из использования |
| Рабочий этап | Planned / In Progress / Complete / Blocked | Состояние выполнения задач |
| Эксперимент | Planned / Active / Successful / Failed / Inconclusive | Состояние и результат проверки |
| ADR | Draft / Accepted / Superseded / Rejected | Согласование и история решения |

Tested требует указания конкретных проверок; Stable — длительной работы и известных ограничений. Prototype сохраняется, если проверен только базовый сценарий.

В metadata Markdown статус этапа записывается InProgress без пробела. Reference у документа означает справочное описание, а не согласование всех проектных деталей.

## Карточка модуля

ID из [Module Index](../00_HOME/Module_Index.md); назначение; входы; выходы; зависимости; код или явное отсутствие; текущее поведение; следующее изменение; проблемы/открытые вопросы; критерий проверки. Связи с ADR и экспериментами добавляются по смыслу.

Близкие компоненты могут иметь разделы с собственными IDs на одной странице. Раздел получает отдельный файл, когда его содержание и жизненный цикл становятся самостоятельными.

## Связи и форматы

Обычные относительные Markdown-ссылки с .md; якоря постоянных разделов-ID латиницей. Mermaid только в fenced блоках, без специальных кликабельных расширений. Файлы без пробелов в имени.

Внутренние диаграммы показывают смысл связей; ссылки на описание расположены рядом. Obsidian graph помогает навигации, но не показывает автоматически смысл зависимости или фактическую готовность.

## Обновление вместе с работой

Затронутый модуль → проверка поведения → описание → Project_Status → текущий этап/задача. Новый важный выбор получает ADR; гипотеза — эксперимент.

Персональные журналы, реальные секреты и модельные файлы не становятся примерами в публичной документации. Используем синтетические данные.

## Завершение этапа

Записать дату, commit, готовый результат, проверки, оставшиеся ограничения и уроки. Не переписывать историю завершения; новый объём работы оформить отдельными задачами.

## Проверка и поддержка

bash scripts/check.sh проверяет поддерживаемое здесь подмножество Markdown: относительные inline-ссылки, файлы и якоря; ID/статусы карточек; синтаксис; базовое восстановление. Внешние URL и визуальный вид диаграмм в редакторах проверяются отдельно.

При новой структуре расширить проверку по реальной необходимости. Не добавлять ручную копию тех же таблиц без указания, какая является канонической.
