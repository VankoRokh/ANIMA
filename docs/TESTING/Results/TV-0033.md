# Stage 4.3 Action / Observation Contracts

## Цель

Подтвердить разделение Stage 4 execution contracts: предложение Planner, системно разрешённое Action, технический ExecutionReceipt, фактическое Observation и отдельные VerificationSpec/VerificationResult должны иметь stable IDs, строгую сериализацию и проверяемые связи без передачи Planner authority завершать Goal.

## Условия

Проверка выполнена владельцем проекта после получения snapshot `a2a669bf967286e2973890b8fe6971e0e772b220`. На нём присутствуют `anima/agent/contracts.py`, targeted tests `tests/test_agent_contracts.py`, ранее подтверждённые Agent storage и Tool Registry, а generated documentation приведена в согласованное состояние.

## Сценарий и входные данные

Выполнены targeted проверки Stage 4.3, полный regression suite и `scripts/check.sh`. Контрольные сценарии покрывают создание и round-trip serialization контрактов, переход `ActionProposal → Action`, привязку Receipt к Action/operation, Observation к конкретному Receipt/Action, VerificationResult к VerificationSpec/evidence, malformed IDs/fields и разорванные cross-contract references.

## Ожидаемый результат

Каждый contract сохраняет типизированную stable identity и восстанавливается из JSON без изменения смысла; `Action` может быть построен только из валидного Tool proposal; ExecutionReceipt сообщает лишь технический результат; Observation описывает факты и не объявляет Goal успешным; VerificationResult требует отдельного VerificationSpec/evidence; dangling или несовместимые ссылки отклоняются.

## Фактический результат

Владелец проекта подтвердил успешное прохождение targeted Stage 4.3 tests, полного regression suite и `scripts/check.sh` на указанном snapshot после исправления generated results index. Ошибок контрактного слоя 4.3 не обнаружено.

## Метрики

Отдельный performance baseline для 4.3 не требуется. Функциональные результаты: targeted Action/Observation contract suite — Passed; полный regression suite — Passed; `scripts/check.sh` — Passed. Latency execution path измеряется позднее.

## Доказано

`ActionProposal`, `Action`, `ExecutionReceipt`, `Observation`, `VerificationSpec` и `VerificationResult` имеют строгие immutable contracts, stable IDs и проверяемые cross-references. Tool success не эквивалентен Goal success. Planner не получает поля, позволяющего самостоятельно объявить безопасность или завершённость Goal. Contract JSON пригоден для последующего persistent/replay контура.

## Не доказано

4.3 не доказывает фактическое исполнение Tool, sandbox isolation, timeout/idempotency side effects, PlannerAdapter, Candidate/Choice integration или применение VerificationResult к GoalProgressEngine. Эти свойства относятся к последующим шагам Stage 4.
