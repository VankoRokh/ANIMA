# Stage 3.5 Deterministic Text Consolidation

## Цель

Подтвердить первый реальный cognitive `CONSOLIDATE` processor: deterministic bounded переработку текстового опыта Event/CLOSED Memory/CONFIRMED Knowledge без скрытого изменения источников.

## Условия

Проверенный snapshot: `99d85198e5f444d2e5b5556a0b56be4a2579b289`. Проверка выполнена владельцем проекта в локальном checkout.

## Сценарий и входные данные

```bash
.venv/bin/python -m pytest -q tests/test_sleep_text_consolidation.py
.venv/bin/python -m pytest -q \
  tests/test_sleep_storage.py \
  tests/test_sleep_contracts.py \
  tests/test_sleep_selection.py \
  tests/test_sleep_processors.py \
  tests/test_sleep_text_consolidation.py
.venv/bin/python -m pytest -q
bash scripts/check.sh
```

Canonical tests используют реальные EventLog/MemoryStore/KnowledgeLayer, OPEN/CLOSED Memories, provisional/confirmed Knowledge, duplicate/empty text fragments и ограниченные `max_items/max_chars`.

## Ожидаемый результат

- Event, CLOSED Memory и CONFIRMED Knowledge читаются через единый text-source adapter;
- OPEN Memory и неподтверждённое Knowledge явно отклоняются;
- whitespace normalization, empty filtering, exact deduplication, grouping и sorting детерминированы;
- bounded result соблюдает `max_items/max_chars`;
- исходные Event/Memory/Knowledge не переписываются, authority Knowledge не повышается и не меняется скрыто.

## Фактический результат

Targeted `tests/test_sleep_text_consolidation.py` завершился результатом 14 passed. Combined Sleep suite 3.1–3.5 дал 70 passed. Полный `pytest -q` и `scripts/check.sh` также прошли успешно; точное число полного regression suite отдельно не фиксировалось.

## Доказано

`DeterministicTextConsolidationProcessor` выполняет первую содержательную Sleep transformation на реальных источниках, при этом остаётся детерминированным, bounded и read-only относительно Event/Memory/Knowledge. Нормализованные дубли не размножаются, output order не зависит от chunk order, а CONFIRMED Knowledge остаётся подтверждённым исходным знанием, а не автоматически переписанным derived result.

## Не доказано

Stage 3.5 не хранит persistent checkpoint между процессами и пока не доказывает interruption/restart equivalence. Derived result ещё не имеет отдельного persistent provenance/output layer Stage 3.7; current `FinalizeResult` является processor-level результатом.
