# Stage 1.11 End-to-End Validation

## Цель

Подтвердить Stage 1 как единый deterministic контур `Event → Memory → Knowledge →
Retrieval → Context Builder`, включая restart/replay, provenance, terminal history
и bounded context, а не только отдельные модули в изоляции.

## Условия

Проверенный snapshot: `dc718d995a12aca90bae38f2640204ddd0df4548`.
Локальная среда владельца проекта: Linux, Python 3.14.4, pytest 9.1.1. Рабочие
данные экземпляра не используются: corpus создаётся во временном каталоге.

## Сценарий и входные данные

```bash
bash scripts/check.sh
.venv/bin/python -m pytest -q
.venv/bin/python -m pytest -v -s tests/test_stage1_validation.py
```

Canonical corpus содержит 37 raw Events в 11 сессиях: lifecycle Events,
продолжение эпизодов, независимые темы, SQLite Entity/alias, поздний возврат к
теме, tool Event, procedural Memory, restart после первых 18 Events, replay уже
обработанного Event, закрытие evidence, Knowledge challenge/supersession,
Retrieval и FAST/DEEP Context.

## Ожидаемый результат

- все 37 raw Events сохраняются и получают final processing-status;
- restart не изменяет уже созданные Memory IDs/effects;
- replay final Event не создаёт дубликаты;
- ожидаемые продолжения дают UPDATE, поздние ветки — CREATE + related_to;
- source Events и Entity anchors сохраняют provenance;
- старое Knowledge проходит confirmed → challenged → superseded, новое становится
  confirmed без перезаписи истории;
- обязательное новое Knowledge находится в заданном Retrieval top-5, а superseded
  Knowledge исключается из current-search;
- exact history retrieval остаётся доступен;
- FAST/DEEP Context соблюдают budgets, FAST не добавляет raw Events, DEEP добавляет
  provenance Events;
- procedural Memory остаётся отдельным типом с raw Event provenance.

## Фактический результат

Пользователь подтвердил `check.sh`, полный regression suite и оба
`tests/test_stage1_validation.py` как зелёные. В первом validation-тесте
подтверждены 37 raw Events, 37 final processing records, 11 episodic Memories,
restart без retry и replay `already_done`. Во втором подтверждены Knowledge
supersession, procedural Memory, Retrieval top-k, Entity/FTS selection,
FAST/DEEP Context и provenance до raw Events.

## Метрики

Stage 1.11 фиксирует функциональную корректность, а не производительность.
Canonical corpus: 37 raw Events / 11 сессий / 11 автоматически сформированных
episodic Memories плюс 1 явная procedural Memory. Latency, CPU, RAM и storage
scaling измеряются отдельно в Stage 1.12.

## Доказано

Компоненты Stage 1 совместимы в одном сценарии: persistent processing переживает
restart/replay, Memory сохраняет source links, Knowledge развивается через
противоречие без стирания прошлого, Retrieval возвращает обязательные current
объекты в заданном top-k, Context Builder ограничивает рабочий контекст и DEEP
восстанавливает provenance до raw Events.

## Не доказано

Не доказан performance baseline на 1k/10k/100k данных и не установлены SLA.
Автоматическое извлечение procedural Memory, автоматическое закрытие эпизодов,
автоматическое создание Knowledge, LLM/Deep Composer, embeddings и Sleep
consolidation остаются вне Stage 1.11.
