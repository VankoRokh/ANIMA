# Stage 3.10 Observability / Resource Budget

## Цель

Подтвердить headless-наблюдаемость SleepJob и определённое resource-budget поведение без отдельного GUI: snapshot/trace должны показывать queue, текущий WorkItem/chunk, progress, processed/skipped/failed counts, причину остановки, budget usage и базовые elapsed/CPU/RAM/storage metrics.

## Условия

Проверенный snapshot: `c64dc6e4b01a979eea97c84fbd33baee83c96b02`. Проверка выполнена владельцем проекта в локальном checkout после исправления trace для post-chunk budget exhaustion.

## Сценарий и входные данные

```bash
.venv/bin/python -m pytest -q tests/test_sleep_observability.py
.venv/bin/python -m pytest -q \
  tests/test_sleep_runtime_integration.py \
  tests/test_sleep_observability.py
.venv/bin/python -m pytest -q \
  tests/test_sleep_storage.py \
  tests/test_sleep_contracts.py \
  tests/test_sleep_selection.py \
  tests/test_sleep_processors.py \
  tests/test_sleep_text_consolidation.py \
  tests/test_sleep_checkpoint_resume.py \
  tests/test_sleep_derived_results.py \
  tests/test_sleep_recovery.py \
  tests/test_sleep_runtime_integration.py \
  tests/test_sleep_observability.py
.venv/bin/python -m pytest -q
bash scripts/check.sh
```

Canonical tests используют bounded chunk, cost и elapsed budgets, exact-fit completion, resume одного WorkItem без повторной оплаты cost, queue с несколькими статусами и headless ScenarioRunner snapshot/trace.

## Ожидаемый результат

- snapshot показывает active Job, queue, WorkItems, текущий chunk и progress;
- budget exhaustion имеет явный `budget:<reason>` и виден также в trace;
- `max_committed_chunks` не допускает новый chunk после исчерпания;
- `max_cost_units` оплачивает логический WorkItem один раз и не штрафует resume повторно;
- elapsed budget останавливает работу на безопасной границе;
- exact-fit budget позволяет normal completion вместо ложного checkpoint;
- CPU/RAM/storage наблюдаются, но на этом шаге не используются как произвольные hard limits.

Targeted `tests/test_sleep_observability.py` завершился результатом 9 passed. Совместная проверка Runtime Integration + Observability дала 17 passed. Combined Sleep suite 3.1–3.10 дала 119 passed. ## Доказано

Sleep progress и причина приостановки доступны без GUI через Runtime snapshot и DiagnosticTrace. Управляющие chunk/cost/elapsed budgets дают определённое поведение на безопасных checkpoint boundaries. Cost usage не удваивается при resume одного WorkItem, а exact-fit chunk budget не создаёт искусственную незавершённость. Базовые process/storage metrics доступны для дальнейшего baseline.

## Не доказано

Stage 3.10 не доказывает bounded-memory обработку многогигабайтного источника и прямой resume с произвольного offset/chunk без повторного чтения начала источника — это Stage 3.11. CPU/RAM/storage пока являются наблюдаемыми метриками, а не откалиброванными hard limits; реальные baseline и bottlenecks будут предметом Stage 3.12.
