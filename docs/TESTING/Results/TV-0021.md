# Stage 3.4 Processor Interface

## Цель

Подтвердить заменяемый processor contract, при котором Sleep orchestration работает с opaque chunks и не знает семантику текста, Asset или будущего source type.

## Условия

Проверенный snapshot: `586561f46988211c765dbc9e97babba6cd6c1203`. Проверка выполнена владельцем проекта в локальном checkout.

## Сценарий и входные данные

```bash
.venv/bin/python -m pytest -q tests/test_sleep_processors.py
.venv/bin/python -m pytest -q \
  tests/test_sleep_storage.py \
  tests/test_sleep_contracts.py \
  tests/test_sleep_selection.py \
  tests/test_sleep_processors.py
.venv/bin/python -m pytest -q
bash scripts/check.sh
```

Тесты используют два разных adapter-а с одним общим `SleepProcessor` contract и проверяют exact name/version resolution, supported source/work kinds, JSON-safe checkpoint/result, identity финального результата и отсутствие silent fallback.

## Ожидаемый результат

- processor capabilities объявлены явно;
- registry разрешает exact processor name/version и не делает fallback;
- initial checkpoint, chunk result и finalize result проходят contract validation;
- source/work/processor identity финального результата совпадает с WorkItem;
- второй adapter может использовать тот же scheduler без специальных веток orchestration.

## Фактический результат

Targeted `tests/test_sleep_processors.py` завершился результатом 11 passed. Combined Sleep suite 3.1–3.4 дал 56 passed. Полный `pytest -q` и `scripts/check.sh` также завершились успешно; точное число полного regression suite отдельно не фиксировалось.

## Доказано

`SleepProcessor` задаёт enforced boundary: orchestration передаёт opaque chunk/checkpoint, adapter возвращает валидируемые `ChunkResult` и `FinalizeResult`, а `ProcessorRegistry` разрешает только явно зарегистрированную capability. Processor/version и source/work identity не могут незаметно измениться на finalize.

## Не доказано

Stage 3.4 не доказывает полезность конкретной cognitive transformation, persistent checkpoint storage, interruption/resume, derived-result storage или provenance полного результата. Реальный deterministic cognitive processor вводится на Stage 3.5.
