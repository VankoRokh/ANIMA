# Stage 6.4 Execution and Independent Verification

## Цель

Подтвердить system-owned execution boundary без возврата AgentRun/AgentStep/Planner semantics и доказать, что успешный side effect сам по себе не считается успехом Goal без независимого Observation/Verification.

## Условия

Проверенный snapshot: `cdba3e90122bf5183377e78559e2baa391c40ea5` в ветке `work/stage6-cognitive-integration`.

Stage 6 использует отдельный `execution.db`, нейтральные ExecutionAction/Operation/Receipt/Observation/Verification contracts и проверенные Stage 4 ToolRegistry/sandbox handlers. FAST/DEEP `PROPOSE_ACTION` остаётся disabled; executable ActionSpec формируется доверенным системным слоем.

## Сценарий и входные данные

Проверены:

- Choice candidate → trusted ActionSpec → ExecutionAction;
- operation ownership через Task + Goal + candidate без AgentRun/AgentStep;
- точное совпадение ActionSpec set с Choice evaluations;
- повторная проверка active Task и active Goal непосредственно перед side effect;
- отдельный persistent `execution.db` и reopen operation state;
- keyed write idempotency и replay без повторного side effect;
- recovery/reconciliation uncertain keyed operation;
- request-hash binding против подмены Action intent;
- успешный ExecutionReceipt не меняет Goal или Task;
- независимый FileObserver перечитывает фактическое состояние sandbox;
- изменение среды после успешного receipt даёт verification failure;
- Goal success возникает только после независимого подтверждения expected content;
- GoalVerificationBridge принимает только связную цепочку VerificationSpec ↔ ExecutionAction ↔ Observation(s) ↔ VerificationResult;
- Stage 4 executor/verification regression tests остаются зелёными.

## Ожидаемый результат

Execution выполняет только system-selected и повторно проверенное действие, operation ledger переживает restart, повтор committed side effect не возникает, а Goal completion требует независимого наблюдаемого evidence.

## Фактический результат

Targeted Stage 6.4 tests, Stage 4 executor/verification regression, project checks и полный pytest suite прошли успешно на указанном snapshot.

## Метрики

Acceptance является correctness/ownership baseline без performance SLA: zero Planner/AgentRun ownership в новом execution path; zero Goal completion от одного ExecutionReceipt; keyed replay/reconciliation не дублирует подтверждённый write; полный regression остаётся зелёным.

## Доказано

Stage 6 имеет отдельный Task/Goal-owned execution ledger и bounded sandbox Executor. Side-effect success и Goal success остаются разными фактами; независимый Observation/Verification является обязательной границей перед GoalProgress. Старый Agent Planner loop для этого не требуется.

## Не доказано

Stage 6.4 не доказывает Sleep lifecycle integration, unified restart recovery всего cognitive loop, model-generated action proposals, semantic writes или произвольные внешние tools. `PROPOSE_ACTION` у FAST/DEEP остаётся намеренно выключенным.

## Итог

Stage 6.4 принят как execution/verification baseline. Следующий slice — 6.5 Sleep Lifecycle Integration: безопасный переход active Task в Sleep и обратно с persistent связью Task ↔ SleepJob и без повторения уже committed side effect.
