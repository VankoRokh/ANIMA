# Stage 1.1 Event Foundation

## Цель

Подтвердить переход raw event history на универсальную схему Stage 1 без потери
Foundation/D1 regression: стабильные event IDs, иерархические типы, source,
session_id, timezone-aware timestamp, references, строгая валидация и обнаружение
duplicate IDs при записи и повторном открытии журнала.

## Условия

Проверенный snapshot указан в метаданных. Локальный прогон выполнен на Linux,
Python 3.14.4, pytest 9.1.1. Перед проверкой старые тестовые instance-data были
сброшены с сохранением identity; временный `memories.jsonl` использует новый
`source="conversation.user"` до замены на SQLite в Stage 1.2.

## Сценарий и входные данные

```bash
bash scripts/check.sh
.venv/bin/python -m pytest -q
.venv/bin/python -m pytest -v -s tests/test_events.py
```

Event-specific набор проверяет `system.wake`, `system.sleep`, `conversation.user`
и универсальный `observation.visual`, UUIDv4 public ID с префиксом `ev_`,
UTC offset, JSON-serializable payload, source/session_id/references, malformed
JSONL, invalid records, duplicate ID и reopen существующей истории.

## Ожидаемый результат

Новая Event schema проходит собственные проверки, полный regression suite остаётся
зелёным, EventLog сохраняет порядок и обнаруживает дубликаты как при записи, так
и после restart/reopen. Новая схема не должна преждевременно вводить SQLite memory
или другие механизмы следующих подэтапов.

## Фактический результат

`bash scripts/check.sh` завершился успешно. Полный pytest: `80 passed in 0.48s`.
Отдельный Event Foundation прогон: `24 passed in 0.06s`. Проверены иерархические
типы, UUIDv4, timezone-aware timestamps, references, invalid inputs, malformed
JSONL, duplicate IDs и reopen history. После исправления переходного контракта
старого MemoryStore все Foundation/D1 интеграционные проверки также прошли.

## Метрики

Документационная проверка: 12 pages, 182 local links, все страницы достижимы;
Python syntax — 36 files, VS Code JSON — 3 files, Bash syntax — 3 files.
Функциональная метрика этого шага — полный pass обязательных Event и regression
проверок; performance требования Stage 1.1 не задавались.

## Доказано

Event Foundation поддерживает стабильные UUIDv4 IDs с type-prefix, timezone-aware
время, source/session_id/references, иерархические event types и строгую
валидацию. EventLog сохраняет порядок, обнаруживает duplicate IDs и корректно
переоткрывает существующую историю. Прежний Runtime/CLI/headless/recovery контур
остаётся работоспособным на новой Event schema.

## Не доказано

SQLite Memory Store, транзакционное состояние обработки Events, долговременные
Entities/Relations/Knowledge, semantic retrieval, Context Builder и performance
масштабирование. Эти свойства относятся к следующим подэтапам Stage 1.
