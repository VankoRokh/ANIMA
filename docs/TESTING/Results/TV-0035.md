# Stage 4.5 PlannerAdapter / Deterministic Planner

## Цель

Подтвердить заменяемую границу планирования: `PlannerAdapter` получает только bounded immutable snapshots Goal/Context/Tools/history/budgets и возвращает структурированный `PlannerTurn` с ограниченным набором `ActionProposal`, не получая authority исполнять Tool или изменять Goal, Memory, Knowledge, AgentStore либо Internal State.

## Условия

Проверка выполнена владельцем проекта после получения изменений из `main` на snapshot `2c63d88c006305f4e77b56e7462152fb4af8861c`. Использован deterministic baseline planner без LLM/provider API. Runtime проекта остаётся stdlib-only.

## Сценарий и входные данные

Выполнены targeted `tests/test_agent_planner.py`, полный regression suite и `scripts/check.sh`. Targeted suite проверяет immutable/bounded `PlannerRequest`, detached Tool descriptors, deterministic strategy boundary, `proposals_available`/`cannot_progress`, proposal count/rank, system Tool validation, request hashing, round-trip contracts и отсутствие writable runtime handles в Planner request.

## Ожидаемый результат

Planner можно заменить без изменения Executor/Choice/Verifier contracts; он видит только разрешённые capability descriptors и bounded snapshots; invalid/unknown Tool proposal отклоняется системным кодом; Planner не может выполнить Tool напрямую или записать Internal State/Goal через собственный интерфейс.

## Фактический результат

Владелец проекта подтвердил успешное прохождение targeted Planner suite, полного regression suite и `scripts/check.sh` на указанном snapshot. Ошибок Stage 4.5 не обнаружено.

## Метрики

Отдельный performance baseline на 4.5 не требуется. Функциональные проверки: targeted PlannerAdapter/DeterministicPlanner suite — Passed; полный regression suite — Passed; `scripts/check.sh` — Passed.

## Доказано

ANIMA имеет provider-neutral Planner boundary и deterministic baseline; Planner request ограничен сериализуемыми immutable snapshots и системными Tool contracts; результат планирования ограничен структурированными proposals/cannot-progress; системная валидация остаётся вне Planner; Internal State не передаётся Planner и поэтому может влиять на действие только через последующий Choice.

## Не доказано

4.5 не доказывает преобразование proposals в Stage 2 Candidates, влияние Internal State на выбор Agent Action, Goal verification, persistence PlannerTurn в `agent.db`, полный Agent loop или качество/стоимость реальной LLM. Эти свойства относятся к следующим шагам Stage 4.
