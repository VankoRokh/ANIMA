# Stage 4.2 Tool Contract / Registry

## Цель

Подтвердить системную границу доступных Agent возможностей: `ToolDescriptor` должен быть неизменяемым версионированным контрактом с input/output schema и metadata side effects/idempotency/effort/timeout/sandbox, а `ToolRegistry` — единственным baseline-источником разрешённых Tool contracts для последующего Planner/Executor контура.

## Условия

Проверка выполнена владельцем проекта после получения изменений из `main` на snapshot `b3dc11259b1f867e84efbc194dfd93d7230e9740`. Runtime проекта остаётся stdlib-only; внешний JSON Schema package не добавлялся. Stage 4.2 реализует только описание и проверку capabilities, без Executor и без реальных файловых side effects.

## Сценарий и входные данные

Выполнены:

```bash
.venv/bin/python -m pytest -vv tests/test_agent_tools.py
.venv/bin/python -m pytest -q
bash scripts/check.sh
```

Targeted suite проверяет валидные и невалидные `ToolDescriptor`, строгий поддерживаемый subset JSON Schema, input/output validation, запрет неизвестных schema keywords и лишних аргументов, immutable nested schema, несколько версий Tool, duplicate registration, lookup/list/planner snapshot и отделение Registry metadata от изменяемого внешнего JSON.

## Ожидаемый результат

Корректный Tool contract регистрируется и однозначно извлекается по `name@version`; invalid schema/metadata/input/output отклоняются явной ошибкой; `read_only` contract не может объявить небезопасную idempotency semantics; неизвестные JSON Schema возможности не игнорируются молча; Planner snapshot не позволяет изменить системный Registry; regressions предыдущих стадий не возникают.

## Фактический результат

Владелец проекта подтвердил успешное прохождение targeted `tests/test_agent_tools.py`, полного regression suite и `scripts/check.sh` на указанном snapshot. Ошибок Stage 4.2 не обнаружено.

## Метрики

Отдельный performance baseline на 4.2 не требуется. Функциональные проверки: targeted Tool contract/registry suite — Passed; полный regression suite — Passed; `scripts/check.sh` — Passed. Стоимость Tool execution и Agent orchestration измеряется позже.

## Доказано

ANIMA имеет собственный строгий и независимый от Planner `ToolDescriptor` contract; Registry поддерживает несколько версий capabilities без перезаписи уже зарегистрированной версии; input/output проверяются системным кодом; nested schema и planner snapshots не дают внешнему коду изменить зарегистрированный contract; unsupported schema syntax fail-closed; реализация не требует сторонней runtime-зависимости.

## Не доказано

4.2 не доказывает `ActionProposal/Action/ExecutionReceipt/Observation` contracts, фактическое исполнение Tool, sandbox path isolation, timeout execution, cross-process idempotency, Planner или Goal verification. Эти свойства относятся к следующим шагам Stage 4.
