# Stage 1.4 Memory Processor

## Цель

Подтвердить deterministic Selection и объяснимый Association для событий памяти:
`skip`, `create`, `update` и `create_related` должны выбираться воспроизводимо,
а причины решения — быть видимыми в diagnostic trace.

## Условия

Проверенный snapshot: `6d580c810d9c69e43f130e78636920567397b175`.
Локальная среда владельца проекта: Linux, Python 3.14.4, pytest 9.1.1.
Рабочие данные экземпляра не используются тестами.

## Сценарий и входные данные

```bash
bash scripts/check.sh
.venv/bin/python -m pytest -q
.venv/bin/python -m pytest -v -s tests/test_trace.py
.venv/bin/python -m pytest -v -s tests/test_memory_processor.py
```

Контрольный corpus включает lifecycle Events, пустой ввод, продолжение эпизода
SQLite, независимый эпизод CM5, возврат к SQLite после большого временного разрыва,
Entity overlap, CLOSED Memory и неизвестную Entity reference.

## Ожидаемый результат

- lifecycle и пустой ввод дают `skip`;
- сильное совпадение обновляет существующую OPEN Memory;
- среднее связанное совпадение создаёт новую Memory + `related_to`;
- независимый ввод создаёт новую Memory;
- CLOSED Memory не переписывается;
- неизвестная Entity reference не принимается молча;
- trace содержит действие, score и причины Association;
- существующая Runtime/D1 регрессия остаётся зелёной.

## Фактический результат

`check.sh` прошёл. Полный regression suite прошёл после обновления ожидаемого
trace-контракта под новые диагностические записи Memory Processor.
`tests/test_memory_processor.py`: 4/4 проверки прошли. Пользователь подтвердил
повторный полный прогон как полностью зелёный.

## Метрики

Точные elapsed/CPU/RAM этого подтверждающего прогона не фиксировались: Stage 1.4
проверяет корректность решений, а не производительность. Performance baseline
остаётся задачей Stage 1.12.

## Доказано

Memory Processor детерминированно отбирает `conversation.user`, ограничивает
кандидатов OPEN episodic Memories, использует session/time/text/Entity signals,
не обновляет CLOSED Memory и выдаёт объяснимое решение `skip/create/update/
create_related`. Runtime использует Processor в обычном рабочем пути, а trace
показывает score и причины решения.

## Не доказано

Не доказано качество смыслового сжатия `Memory.content`: UPDATE пока добавляет
новую строку без полноценной композиции. Не проверены Merge/History, Knowledge
lifecycle, общий Retrieval/Context Builder, crash-idempotency и масштабирование.
Эти свойства относятся к последующим шагам Stage 1.
