Подтвердить Stage 6 как единый system-owned cognitive integration core: persistent Goal/Task, deterministic resolution, FAST/DEEP routing, bounded Internal State + Choice, Sleep lifecycle, validated execution, independent verification, controlled restart/recovery и persistent causal trace без передачи LLM системного ownership.

## Сценарий и входные данные

Основной controlled-restart сценарий использовал один persistent Goal и связанный active Task.

Внутри одного causal lifecycle были последовательно проверены:

1. bounded unresolved task → FAST route;
2. explicit conflict reasoning → DEEP route;
3. `CHOOSE_ACTION` → system-owned Choice;
4. bounded Internal State modifiers и выбранный candidate;
5. Sleep enter/work/wake с сохранением Task lifecycle;
6. system-validated `ExecutionAction` и `VerificationSpec`;
7. keyed `fs.write` с controlled crash-point после фактического side effect, но до commit operation outcome;
8. реконструкция владельцев state из persistent stores после restart;
9. recovery `executing → uncertain`;
10. загрузка exact validated `ExecutionAction` и `VerificationSpec` из `execution.db` schema v2;
11. reconciliation уже существующего write без повторного side effect;
12. independent file observation;
13. deterministic verification;
14. Goal completion только через verification bridge;
15. Task completion и закрытие persistent unified trace.

Отдельные acceptance cases проверили deterministic no-model route, insufficient-data no-model route, disabled/invalid proposal rejection, backend failure isolation, FAST/DEEP backend replacement без переноса Identity/Memory/Task/Goal state и Sleep checkpoint/resume после process restart.

## Ожидаемый результат

Stage 6 считается завершённым только если один persistent Task/Goal lifecycle переживает controlled restart, уже произошедший keyed side effect не повторяется, verification использует независимое evidence, FAST/DEEP/CHOICE routing остаётся system-owned и наблюдаемым, backend replacement не переносит системное состояние, Internal State влияет только через bounded Choice rules, Sleep resume не теряет Task, а deterministic/insufficient paths не вызывают модели без необходимости.

Все существующие regressions предыдущих Stage должны остаться зелёными.

## Фактический результат

Все заявленные Stage 6.8 acceptance checks и полный regression прошли успешно.

Controlled restart доказал восстановление не только operation metadata, но и exact validated execution intent: `ExecutionAction` и `VerificationSpec` после restart были заново загружены из SQLite, а не переиспользованы из pre-restart Python memory. Operation, найденная в `executing`, была нормализована в `uncertain`, после чего keyed reconciliation подтвердила уже применённый write без повторной записи.

Independent Observation/Verification подтвердили Goal criterion, после чего Goal и Task завершились через свои system-owned lifecycle boundaries. Persistent unified trace сохранил последовательную причинную историю до и после restart.

FAST, DEEP и CHOICE были представлены в одном acceptance lifecycle; модели оставались proposal backends без прямого persistence/execution ownership.
