# Stage 1.5 Memory Composer

## Цель

Подтвердить отдельный deterministic `RuleBasedComposer`, который формирует
ограниченный `Memory.content` независимо от Association: нормализует вход,
убирает повторы, при переполнении бюджета сохраняет более значимые смысловые
единицы и допускает замену другим Composer без изменения Memory Processor.

## Условия

Проверенный snapshot: `81c822c13ff460a7a9befff24b7a1dba6e2a6d68`.
Локальная среда владельца проекта: Linux, Python 3.14.4, pytest 9.1.1.
Рабочие данные экземпляра тестами не используются.

## Сценарий и входные данные

```bash
bash scripts/check.sh
.venv/bin/python -m pytest -q
.venv/bin/python -m pytest -v -s \
  tests/test_memory_composer.py \
  tests/test_memory_composer_revision.py
.venv/bin/python -m pytest -v -s tests/test_memory_processor.py
```

Проверяются CREATE/UPDATE, точная дедупликация, лимит `max_chars`, приоритет
решений/результатов/изменений/ограничений/причин/открытых вопросов,
детерминизм, подменяемость Composer и консервативная ревизия расширенного либо
явно заменяющего факта.

## Ожидаемый результат

- одинаковый вход даёт одинаковый `content`;
- точные повторы не размножаются;
- результат не превышает заданный character budget;
- при нехватке бюджета сохраняются более значимые смысловые единицы;
- более полный новый факт может заменить короткую предыдущую формулировку;
- явная замена старого решения не требует сохранения обоих вариантов;
- Memory Processor использует Composer через заменяемый интерфейс;
- Association и предыдущая регрессия не ломаются.

## Фактический результат

Пользователь подтвердил `check.sh`, полный regression suite, Composer tests и
Memory Processor tests как полностью зелёные на указанном snapshot.

## Метрики

Performance-метрики этого прогона отдельно не фиксировались. На Stage 1.5
проверяется корректность и воспроизводимость композиции; latency/CPU/RAM и
масштабирование измеряются в Stage 1.12.

## Доказано

Формирование `Memory.content` отделено от Association. `RuleBasedComposer`
детерминированно нормализует и дедуплицирует смысловые единицы, соблюдает явный
character budget и при необходимости сохраняет более важные категории. Processor
может работать с другим объектом Composer того же контракта без изменения своей
логики выбора Memory.

## Не доказано

Rule-based baseline не является полноценным семантическим суммаризатором и не
заменяет будущий Small/Deep Composer. Не доказаны Merge/History, Knowledge
lifecycle, общий Retrieval/Context Builder, crash-idempotency и качество на
длинных естественных диалогах; эти свойства относятся к последующим шагам.
