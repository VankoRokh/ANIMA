# Stage 1.3 Entities / Relations / Provenance

## Цель

Подтвердить минимальный слой Entity/Relation и восстанавливаемое происхождение
данных от Knowledge, Entity и Relation через Memory до фактических raw Events.
Entity resolution должен оставаться консервативным: неоднозначность не приводит
к автоматическому объединению сущностей.

## Условия

Проверенный snapshot: `b24fbab9059ac95300c59c0c4866e9d966d85f12`.
Linux, Python 3.14.4, pytest 9.1.1. Проверки выполняются на временных SQLite/JSONL
данных и не используют рабочий экземпляр ANIMA.

## Сценарий и входные данные

```bash
bash scripts/check.sh
.venv/bin/python -m pytest -q
.venv/bin/python -m pytest -v -s tests/test_provenance.py
```

Контрольный сценарий использует две Memories и два raw Events о выборе SQLite и
последующем обнаружении ограничения, одну Knowledge-запись, Entity SQLite и связи
`supports`, `contradicts`, `about`. Отдельно проверяются неоднозначный alias,
неверное направление Relation, дубликат Relation и отсутствующий source Event.

## Ожидаемый результат

- полный regression suite и project checks проходят;
- canonical name/alias/normalization разрешают однозначную Entity;
- неоднозначный alias даёт определённую ошибку без auto-merge;
- Relation принимает только разрешённые направления и существующие объекты;
- эквивалентный Relation не дублируется;
- `Memory → Event`, `Knowledge → Memory → Event`, `Entity → Memory → Event` и
  `Relation → Memory → Event` восстанавливаются до raw Event;
- отсутствующий raw Event обнаруживается как нарушение provenance.

## Фактический результат

Пользователь подтвердил зелёный `check.sh` и полный regression suite после
исправления обязательных секций TV-0005. Отдельный `tests/test_provenance.py`
прошёл полностью: 4 из 4 тестов.

## Метрики

Stage 1.3 validation: `4/4` специализированных provenance-теста прошли. Полный
regression suite также прошёл без ошибок; performance/latency на этом шаге не
измерялись и не оптимизировались.

## Доказано

Entity aliases разрешаются детерминированно и консервативно; универсальная таблица
Relations проверяет допустимые направления и требует `source_memory_id` как
доказательную опору. ProvenanceResolver восстанавливает источник Memory/Knowledge/
Entity/Relation до существующей записи `events.jsonl` и сообщает о потерянном
source Event.

## Не доказано

Не доказаны автоматическое извлечение Entities из произвольного текста, сложный
Entity Resolution, Memory Association/Processor, Composer, Knowledge lifecycle,
Retrieval/Context Builder, idempotent processing и производительность на больших
объёмах. Создание Knowledge в 1.3 — минимальная опора для provenance, а не
реализация правил формирования и пересмотра знаний Stage 1.7.
