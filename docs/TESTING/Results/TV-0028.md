# Stage 3.11 Large-data Readiness

## Цель

Подтвердить, что Sleep orchestration способен обрабатывать логически многогигабайтный Asset как ленивый resumable source: полный payload не материализуется в RAM или `sleep.db`, а после interruption/restart чтение продолжается непосредственно с первого незавершённого chunk.

## Условия

Проверенный snapshot: `5b4ec4fe08f390921fd7349f4b81d8d331c10b6e`. Проверка выполнена владельцем проекта в локальном checkout. Synthetic source моделирует Asset логического размера 10 GiB с chunk size 5 MiB и 2048 chunks; материализованный sample одного chunk ограничен 4096 байтами.

Canonical large-data scenarios включают прямой `iter_from(N)`, interruption после 123 committed chunks, reopen `sleep.db`, resume с chunk 123, сравнение memory peak для 10 GiB и 100 GiB logical sources, bounded checkpoint/local-result metadata и compatibility с прежним plain iterable contract.

## Ожидаемый результат

- logical source размером не менее 10 GiB не требует создания полного payload;
- executor при resumable source начинает чтение непосредственно с `resumed_from_sequence`;
- interruption/reopen/resume не перечитывает уже committed chunks;
- память зависит от materialized chunk/sample, а не линейно от общего logical size;
- checkpoint/local result остаются bounded metadata и не накапливают payload;
- `sleep.db` хранит refs/checkpoints/results, но не многогигабайтный Asset;
- старый iterable-path checkpoint/resume остаётся совместимым.

## Доказано

Synthetic Asset логического размера 10 GiB проходит bounded chunk processing без materialization полного payload. После interruption на 123 chunks новый executor после reopen начинает источник с `iter_from(123)`, поэтому уже committed диапазон не читается повторно. Memory peak для фиксированного префикса остаётся bounded при увеличении logical size с 10 GiB до 100 GiB, а checkpoint/local-result содержат только компактные metadata. Plain iterable contract предыдущих этапов сохранён.

## Не доказано

Stage 3.11 не измеряет production throughput или масштабирование scheduler/checkpoint/provenance на 1k/10k/100k WorkItems — это Stage 3.12. Synthetic source доказывает архитектурный large-data contract, но не скорость реального диска, декодирования видео/аудио, сетевого storage или конкретного media processor. Реальные Asset adapters и их содержательная обработка остаются будущими задачами.
