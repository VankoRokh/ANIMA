# Stage 1.9 Context Builder

## Цель

Подтвердить read-only Context Builder, который превращает объяснимый Retrieval в
ограниченный рабочий `ContextBundle` для разных consumers и строго соблюдает
`max_items/max_chars` без скрытого изменения Memory/Knowledge.

## Условия

Проверенный snapshot: `9f7ce827f14343cb28a1e9e2c230168c735f888e`.
Локальная среда владельца проекта: Linux, Python 3.14.4, pytest 9.1.1.
Рабочие данные экземпляра тестами не используются.

## Сценарий и входные данные

```bash
bash scripts/check.sh
.venv/bin/python -m pytest -q
.venv/bin/python -m pytest -v -s tests/test_context_builder.py
```

Canonical corpus содержит подтверждённое Knowledge, несколько Memories и raw
Events с общим provenance. Проверяются FAST/DEEP policies, exact-ID priority,
Knowledge-first selection, item/character budgets, deduplication raw Events,
structured Retrieval filters и invalid policy/budget requests.

## Ожидаемый результат

- одинаковый вход и policy дают одинаковый `ContextBundle`;
- exact ID не вытесняется связанным Knowledge при тесном budget;
- после exact result Knowledge выбирается раньше Memories;
- FAST не добавляет raw Events, DEEP добавляет deduplicated provenance Events;
- `max_items` и `max_chars` никогда не превышаются;
- запись, не помещающаяся целиком, пропускается, а не обрезается;
- `truncated` и selection statistics отражают ограничение;
- Context Builder не мутирует storage.

## Фактический результат

Пользователь подтвердил `check.sh`, полный regression suite и отдельный
`tests/test_context_builder.py` как полностью зелёные на указанном snapshot.

## Метрики

Performance-метрики отдельно не фиксировались. Stage 1.9 проверяет корректность,
детерминизм и budget behavior; latency/CPU/RAM измеряются в Stage 1.12.

## Доказано

`ContextBuilder` разделяет Retrieval и рабочий контекст, поддерживает FAST/DEEP
read policies, сохраняет причины отбора, дедуплицирует provenance Events и строго
соблюдает item/character budgets. Exact lookup имеет приоритет, а обычная выборка
предпочитает Knowledge перед Memory; raw Events добавляются после них.

## Не доказано

Не доказаны persistent event processing, crash recovery/idempotency, общий
end-to-end corpus Stage 1 и performance baseline. Token-aware budget и реальные
model-specific context policies намеренно отложены до появления конкретных
моделей/consumers.
