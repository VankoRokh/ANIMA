# Stage 2.13 End-to-End Validation

## Цель

Подтвердить Definition of Done Stage 2 Internal State на связных канонических сценариях: Goals, четыре baseline state, причинные transitions, time dynamics, Choice, Expression, Runtime integration и restart/replay. Одновременно подтвердить, что полный regression suite предыдущих этапов остаётся зелёным.

## Условия

Проверенный snapshot: `36c8d65248a58d9dfd548c6aa181f9badcdb4b40`.
Проверка выполнена владельцем проекта в локальном Git checkout на основном рабочем окружении. Stage 2 Decision Performance baseline ранее отдельно зафиксирован в [TV-0016](TV-0016.md). Документационные изменения после этого snapshot не считаются частью проверенного кода.

## Сценарий и входные данные

```bash
git pull
./scripts/check.sh
pytest -q tests/test_stage2_validation.py
pytest -q
pytest -v -s tests/test_stage2_validation.py
```

Канонический набор `tests/test_stage2_validation.py` использует существующие Runtime/public boundaries и не вводит отдельную production-логику специально ради проверки. Сценарии покрывают neutral/altered Choice, fatigue, uncertainty, frustration, satisfaction, Goal lifecycle/arbitration, lazy time dynamics, Expression, causal trace, ScenarioRunner и reopen/replay.

## Ожидаемый результат

- targeted Stage 2 validation проходит полностью;
- полный regression suite остаётся зелёным;
- Internal State влияет на Candidate evaluation, но не создаёт и не подменяет Goal/Candidate;
- четыре состояния изменяются только через причинно прослеживаемые transitions и соблюдают диапазон;
- uncertainty не уменьшается только из-за времени, а остальные time rules воспроизводимы при injected time;
- verified progress/result меняют Goal/state предсказуемо, unverified result не получает authority;
- Expression остаётся read-only зависимым отображением state;
- replay/restart не дублируют source effects и не создают time drift;
- один и тот же вход и время дают воспроизводимый Choice и trace.

## Фактический результат

Все проверки прошли успешно. Targeted Stage 2 validation завершился как `13 passed`. Полный regression suite завершился как `306 passed`. Повтор targeted-набора в verbose/observable режиме также завершился как `13 passed`. `./scripts/check.sh` прошёл без ошибок.

Ни один из канонических сценариев не потребовал ослабления invariant ADR-006: Internal State остался bounded регулирующим входом, Goal authority и Candidate creation не были переданы state layer. Restart/replay и lazy time сохранили согласованность, а Expression не создал скрытого feedback path.

## Доказано

Stage 2 имеет работающий deterministic baseline `Goal + Situation → Candidates → base evaluation + bounded Internal State modifiers → Choice`, где причина изменений state и итогового выбора наблюдаема. Реализованы и совместно прошли проверку: transactional `internal_state.db`, causal StateTransition history, Goal lifecycle/arbitration, четыре baseline state, event/result transition rules, lazy time dynamics, verified Goal progress/result, Choice score trace, read-only ExpressionProfile, headless Runtime integration и persistent source recovery/idempotency.

Доказано, что completed/cancelled/blocked состояния цели обрабатываются по заданному lifecycle, repeated failure и success имеют разные repetition semantics, restart/replay не размножают эффекты, а Decision Engine при 100 Candidates сохраняет миллисекундный порядок стоимости даже с полной диагностикой.

## Не доказано

Stage 2 не доказывает автономное целеполагание, планирование, субъективные эмоции или сознание. Candidates по-прежнему задаются внешним consumer/scenario; raw Events не интерпретируются автоматически как психологический смысл без явного StateSignal/GoalObservation. ExpressionProfile ещё не является конкретным голосом, текстовым стилем или UI. Реальные CPU/GPU/power signals не подключены к fatigue. Sleep consolidation, Deep/LLM обработка, Agent tools и автономное выполнение задач относятся к следующим этапам.
