# TV-0041 — Stage 4.11 Recovery / Interruption / Replay

## Цель

Подтвердить, что AgentRun восстанавливается после restart/crash на сохранённых границах без повторения подтверждённого side effect, второго Goal success или дублирования Stage 2 state effects.

## Условия

Проверка выполнена владельцем проекта локально на snapshot `c823932bbdb50ccdf05b80ec2ea22b63ad2ca27b`. Использованы persistent `agent.db`, recovery journal, sandbox Executor и существующий Stage 2 RecoveryLedger. После исправления формата TV-0040 полный regression suite и `scripts/check.sh` прошли без ошибок.

## Сценарий и входные данные

Fault-injection покрывает crash после сохранения PlannerTurn, Action/AgentOperation, выполнения Tool, сохранения Receipt, Observation, VerificationResult, применения Goal progress и завершения Step. Отдельно моделируется crash между применением Stage 2 `VerificationResult` и фиксацией `goal_applied` в `agent.db`.

## Ожидаемый результат

Resume использует те же stable Action/Operation/Verification IDs, не повторяет confirmed keyed write, не создаёт второй Goal transition и не применяет один и тот же verification source к Internal State повторно. Persisted artifacts остаются immutable и восстанавливаются после reopen.

## Фактический результат

Владелец проекта подтвердил успешное прохождение targeted recovery suite, полного regression suite и `scripts/check.sh`. Документационные ошибки были отдельными ошибками формата отчёта TV-0040 и после их исправления проверки стали зелёными; recovery-код дополнительных исправлений не потребовал.

## Метрики

Отдельный performance baseline на 4.11 не выполнялся. Функциональные критерии: targeted recovery tests — Passed; полный regression suite — Passed; documentation/check script — Passed. Количество и timing тестов не фиксируются как показательная метрика.

## Доказано

Recoverable AgentLoop может продолжить persisted Run после crash на основных execution/observation/verification boundaries; keyed side effect не повторяется после потери runtime Receipt; cross-store replay одного `vr_...` дедуплицируется Stage 2 RecoveryLedger; completed Goal согласуется с Run lifecycle после restart.

## Не доказано
