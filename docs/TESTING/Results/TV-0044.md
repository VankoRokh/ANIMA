# Stage 6.0 Persistent Task Foundation

## Цель

Подтвердить новый system-owned persistent Task baseline как отдельную сущность Stage 6 без Planner/LLM semantics и без смешения с Goal, CanonicalTask или AgentRun.

## Условия

Проверенный snapshot: `aa3349b8ad97bbb6826128a65221e554e0b1c870` в ветке `work/stage6-cognitive-integration`.

Реализация использует отдельный `tasks.db`, типизированные `Task`/`TaskTransition` contracts и `TaskStore`. Существующие Stage 2–5 stores, Runtime и cognitive contracts этим slice не изменяются.

## Сценарий и входные данные

Проверены:

- создание persistent Task с `task_<UUIDv4>`;
- optional `goal_id` и source metadata без cross-database foreign key;
- чтение и фильтрованный list;
- lifecycle `queued → active → interrupted → active → completed`;
- альтернативные terminal outcomes `failed` и `cancelled`;
- запрет invalid transitions и resume terminal Task;
- append-only transition history;
- reopen `tasks.db` как имитация restart;
- сохранение Task и полной transition history после reopen;
- atomic rollback при сбое transition write;
- отсутствие model/backend/planner полей и скрытого ownership над Goal или другими stores;
- достижимость новой Stage 6 specification из основной документации.

Команды проверки:

```bash
.venv/bin/python -m pytest -q tests/test_task_store.py
.venv/bin/python -m pytest -q tests/test_documentation.py
.venv/bin/python -m pytest -q
```

## Ожидаемый результат

Task persistence и lifecycle работают независимо от LLM/Planner; invalid и terminal transitions отклоняются; restart сохраняет состояние и историю; ошибка записи transition не оставляет частично изменённый Task; новый slice не ломает существующий regression suite.

## Фактический результат

Targeted TaskStore tests, documentation tests и полный regression suite прошли успешно на указанном snapshot.

## Метрики

Stage 6.0 — foundation slice без performance SLA. Ключевые метрики: все targeted проверки проходят; reopen сохраняет Task/history; transition mutation атомарна; regression suite остаётся зелёным. Отдельный performance baseline для TaskStore на этом этапе не требуется.

## Доказано

Persistent Task может существовать как отдельная system-owned сущность, переживать restart, иметь явный lifecycle и history без зависимости от Planner, FAST/DEEP backend или AgentRun. Базовая граница `Goal ≠ Task ≠ CanonicalTask ≠ Action` не требует объединения их хранилищ.

## Не доказано

Stage 6.0 не доказывает Cognitive Coordinator, FAST/DEEP routing, CognitiveProposal, влияние Internal State на реальные action candidates, execution/verification integration, Sleep lifecycle integration или end-to-end recovery интегрированного cognitive loop. Это последующие slices Stage 6.

## Итог

Stage 6.0 — Persistent Task Foundation принят как рабочий baseline. Следующий slice — 6.1 Cognitive Coordinator поверх существующего Stage 5 resolution path без передачи модели orchestration ownership.
