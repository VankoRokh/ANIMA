# Stage 1.7 Knowledge Layer

## Цель

Подтвердить явный Knowledge lifecycle с Memory-backed evidence и provenance:
`provisional → confirmed → challenged → confirmed/superseded/rejected`, без
молчаливой перезаписи старого знания и без автоматического превращения любой
Memory в Knowledge.

## Условия

Проверенный snapshot: `c4f75fae94c6259cf7e59209c06df04191448949`.
Локальная среда владельца проекта: Linux, Python 3.14.4, pytest 9.1.1.
Рабочие данные экземпляра тестами не используются.

## Сценарий и входные данные

```bash
bash scripts/check.sh
.venv/bin/python -m pytest -q
.venv/bin/python -m pytest -v -s \
  tests/test_knowledge.py \
  tests/test_knowledge_evidence.py
```

Проверяются создание Knowledge только из CLOSED Memory, provisional/confirmed,
investigation без challenge, CLOSED contradiction, reconfirm с новым evidence,
supersession без overwrite, rejection, терминальные состояния, конфликт
support/contradict, provenance и временная последовательность переходов.

## Ожидаемый результат

- Knowledge candidate требует CLOSED source Memory;
- создание кандидата формирует `supports` relation с provenance;
- investigation сама по себе не меняет `confirmed` на `challenged`;
- CLOSED contradiction переводит только `confirmed → challenged`;
- challenged Knowledge требует нового supporting evidence для reconfirm;
- confirmed нельзя напрямую перевести в rejected/superseded;
- supersession создаёт новую confirmed Knowledge и сохраняет старую как superseded;
- rejected/superseded не открывают новые investigation branches;
- одна Memory не может одновременно support и contradict одно Knowledge;
- все переходы остаются прослеживаемыми до raw Events;
- полный regression suite остаётся зелёным.

## Фактический результат

После исправления стабильного documentation-anchor пользователь подтвердил
`check.sh` и полный regression suite как полностью зелёные. Отдельные Knowledge
suites прошли 8/8 проверок.

## Метрики

Отдельные latency/CPU/RAM не фиксировались. Stage 1.7 проверяет state machine,
целостность evidence и provenance; performance baseline относится к Stage 1.12.

## Доказано

`KnowledgeLayer` отделяет Knowledge lifecycle от Memory Processor. Knowledge
создаётся только из CLOSED evidence, поддерживающие/противоречащие источники
хранятся как универсальные Relations, investigation не считается противоречием,
challenge требует реального CLOSED evidence, а supersession сохраняет старое
утверждение и создаёт новое. История переходов и `Knowledge → Memory → Event`
provenance сохраняются.

## Не доказано

Не доказаны общий Retrieval/ranking, Context Builder, crash-idempotency,
автоматическое принятие Knowledge моделью, embeddings/semantic search и
масштабирование. Эти свойства относятся к последующим шагам Stage 1.
