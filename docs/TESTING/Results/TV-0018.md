# Stage 3.1 Sleep Storage / Lifecycle

## Цель

Подтвердить persistent transactional storage для SleepJob как основу Stage 3: отдельный `sleep.db`, стабильную идентичность job, определённый lifecycle `queued/running/checkpointed/interrupted/completed/failed`, сохранение состояния после reopen и защиту от недопустимых переходов.

## Условия

Проверенный snapshot: `9101154553fccbebaeb139a6fd2898ab10071101`.
Проверка выполнена владельцем проекта в локальном Git checkout после получения изменений Stage 3.1. Документационные изменения, фиксирующие результат и переводящие текущий фокус на Stage 3.2, выполняются после проверенного snapshot и не считаются частью проверенного кода.

## Сценарий и входные данные

```bash
git pull --ff-only
.venv/bin/python -m pytest -q tests/test_sleep_storage.py
.venv/bin/python -m pytest -q
bash scripts/check.sh
```

Targeted suite создаёт временные `sleep.db` и проверяет schema/version, создание queued job, reopen, transaction rollback, SQLite constraints/foreign keys, стабильный ID, timestamp validation, допустимые resume/retry paths и запрещённые lifecycle transitions. Рабочие данные экземпляра не используются.

## Ожидаемый результат

- `sleep.db` создаётся как отдельное transactional storage и использует `ANIMA_DATA_DIR` по общим правилам проекта;
- SleepJob получает стабильный `sj_<UUIDv4>` и начинает lifecycle в `queued`;
- reopen сохраняет тот же job ID и последнее committed состояние;
- status и transition history изменяются одной transaction;
- invalid lifecycle transition не изменяет job и не добавляет ложную history;
- `completed` остаётся terminal, resume из `interrupted` выполняется явно, retry после `failed` требует перехода обратно в `queued`;
- полный regression suite предыдущих этапов и project check остаются зелёными.

## Фактический результат

Все запрошенные проверки прошли успешно. Targeted `tests/test_sleep_storage.py` содержит 14 test cases и завершился без ошибок. Полный `pytest -q` и `scripts/check.sh` также завершились успешно; точное число тестов полного regression suite в этот отчёт не переносится, поскольку оно не было отдельно зафиксировано в сообщении о прогоне.

Проверка не потребовала изменения invariants ADR-007. Sleep orchestration остаётся отдельным storage и пока не владеет source payload или cognitive semantics.

## Доказано

Реализован и проверен первый persistent слой Sleep: `SleepStore` создаёт отдельный `sleep.db`, хранит SleepJob и его transition history, использует schema version и foreign keys, выполняет изменения через `BEGIN IMMEDIATE` transaction и переживает reopen без потери identity/status. Lifecycle запрещает прямые недопустимые переходы, делает `completed` terminal и требует явных действий для resume/retry.

Тем самым выполнен критерий Stage 3.1: schema/reopen/constraints/rollback работают, invalid transitions определены, а restart сохраняет job identity и последнее допустимое committed состояние.

## Не доказано

Stage 3.1 ещё не реализует `SourceRef`, `WorkItem`, scheduler, resource budget, processor contract, реальное checkpoint содержимого, chunk execution, derived results, provenance между Sleep и Memory/Knowledge, cross-store recovery или Runtime integration. Статус `checkpointed` на этом шаге является частью lifecycle job, но сам механизм cursor/checkpoint данных будет доказан последующими шагами Stage 3.
