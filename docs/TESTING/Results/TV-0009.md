# Stage 1.6 Merge and History

## Цель

Подтвердить явный lifecycle `OPEN/CLOSED/MERGED`, безопасный Merge без потери
provenance и компактную историю существенных изменений Memory.

## Условия

Проверенный snapshot: `e71973863fb41204bdf2a547b710d69cbef234cb`.
Локальная среда владельца проекта: Linux, Python 3.14.4, pytest 9.1.1.
Рабочие данные экземпляра тестами не используются.

## Сценарий и входные данные

```bash
bash scripts/check.sh
.venv/bin/python -m pytest -q
.venv/bin/python -m pytest -v -s tests/test_memory_lifecycle.py
```

Проверяются закрытие OPEN Memory, Merge OPEN/CLOSED source в OPEN target,
сохранение source-записи, перенос source Event provenance и Entity anchors,
history records, несовместимые type/domain, self-merge, CLOSED target и временная
последовательность операций.

## Ожидаемый результат

- только OPEN Memory можно закрыть;
- merged source остаётся отдельной записью со статусом `merged` и `merged_into`;
- target получает source Event links и недостающие активные `about` Entity links;
- source сохраняет собственные content/provenance links;
- Merge выполняется атомарно в одной SQLite-транзакции;
- история фиксирует close и обе стороны Merge;
- недопустимые переходы не мутируют данные;
- timestamp lifecycle не движется назад;
- предыдущая регрессия остаётся зелёной.

## Фактический результат

Пользователь подтвердил `check.sh`, полный regression suite и отдельный
`tests/test_memory_lifecycle.py` как полностью зелёные на указанном snapshot.

## Метрики

Отдельные latency/CPU/RAM не фиксировались. Stage 1.6 проверяет целостность
lifecycle/provenance; performance baseline остаётся задачей Stage 1.12.

## Доказано

`MemoryLifecycle` реализует контролируемые `OPEN → CLOSED` и `OPEN/CLOSED → MERGED`
операции. Merge сохраняет исходную Memory, копирует недостающие source Events и
Entity anchors в target, фиксирует изменения в `history` и откатывается целиком
при ошибке транзакции. Временные метки lifecycle не могут предшествовать
последнему изменению участвующей Memory.

## Не доказано

Не доказаны Knowledge lifecycle, автоматическое решение когда закрывать/merge
Memories, SPLIT, общий Retrieval/Context Builder, crash-idempotency и
масштабирование. SPLIT намеренно не входит в Stage 1 baseline; остальные свойства
проверяются последующими шагами.
