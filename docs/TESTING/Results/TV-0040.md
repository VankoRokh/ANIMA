# TV-0040 — Stage 4.10 Memory Integration

## Цель

Подтвердить, что значимый опыт AgentRun проходит через обычный Event/Memory processing path и формирует один bounded episodic Memory вместо отдельной Memory на каждый технический Tool call.

## Условия

Проверка выполнена владельцем проекта на snapshot `5c0afb98b816ba9cdd7a8b6de4d418c93e28f18e` после завершения Stage 4.10. Использованы существующие `EventLog`, `MemoryStore`, `MemoryProcessor` primitives и `EventProcessingCoordinator`; отдельный Agent experience processor имеет собственные processor name/version и не изменяет обработку пользовательских `conversation.user` Events.

## Сценарий и входные данные

Canonical AgentRun публикует компактную цепочку значимых `agent.*` Events: failure, strategy change, обратимое action, подтверждающее observation и итоговый result. Эти Events передаются в Agent Memory integration. Дополнительно проверяются повторная обработка уже завершённого Run и recovery-сценарий, где raw Events уже опубликованы, но episodic Memory ещё не создана.

## Ожидаемый результат

Промежуточные `agent.*` Events не должны создавать отдельные Memories. `agent.result` должен детерминированно консолидировать весь значимый Run в одну bounded episodic Memory домена `self`; provenance должен включать все значимые source Event IDs. Replay/recovery не должны создавать вторую Memory, а пользовательский Stage 1 processing path не должен изменяться.

## Фактический результат

Владелец проекта подтвердил успешное прохождение targeted `tests/test_agent_memory_integration.py`, полного regression suite и `scripts/check.sh`. Canonical Run сформировал одну episodic Memory с failure, strategy adjustment, значимым action, verification и итогом Run/Goal; все значимые `agent.*` Events сохранились как provenance sources. Повторная обработка и recovery не создали дубликат Memory.

## Метрики

Отдельный performance baseline на Stage 4.10 не снимался. Функциональные проверки: targeted Memory Integration suite — Passed; полный regression suite — Passed; `scripts/check.sh` — Passed. Точное число тестов и timing не фиксируются, поскольку они не были сохранены как показательные метрики этой проверки.

## Доказано

Значимый Agent experience может пройти через обычную Event/Memory processing границу и быть сконсолидирован в одну bounded episodic Memory домена `self`; промежуточные технические события не размножают Memories; provenance восстанавливает цепочку до source Events; exactly-once/recovery механизмы существующего `EventProcessingCoordinator` предотвращают повторное создание эпизода.

## Не доказано

Stage 4.10 не доказывает полный restart/resume незавершённого AgentRun, recovery structured Action/Receipt/Observation/Verification artifacts, отсутствие повторного side effect после crash или интеграцию реальной LLM. Эти свойства относятся к Stage 4.11–4.12 и финальной валидации Stage 4.
