# Stage 6.6 Recovery and Unified Trace

## Цель

Подтвердить persistent causal trace Stage 6 и межмодульный restart recovery без передачи trace/recovery ownership над Task, Goal, Memory, Execution или Sleep.

## Условия

Проверенный snapshot: `010949a1b8ff2cf223af7d706d2529d1adfc7836` в ветке `work/stage6-cognitive-integration`.

Stage 6 использует отдельный `trace.db`; существующие Task/Goal/Execution/Sleep stores остаются источниками истины собственных состояний.

## Сценарий и входные данные

Проверены:

- один persistent trace через resolution, DEEP route, proposal validation, Choice, Sleep, execution, independent observation/verification и final Task/Goal outcome;
- сохранение Task ID, Goal ID, CanonicalTask/source, route reason/policy, context/provenance summary, Choice modifiers, Action/Operation, Observation/Verification и Sleep refs;
- reopen `trace.db` после restart с сохранением ordered events;
- `executing` operation нормализуется в `uncertain`, а не объявляется succeeded и не запускается слепо повторно;
- `prepared` остаётся prepared;
- `succeeded` остаётся succeeded;
- существующий keyed reconciliation переводит uncertain operation в succeeded без повторного write;
- committed side effect не повторяется после restart;
- Sleep recovery остаётся делегирован TaskSleepCoordinator/Stage 3 runtime;
- trace является evidence layer и не владеет persistent system state.

## Ожидаемый результат

Незавершённый Stage 6 Task после controlled restart продолжает работу с той же причинной трассой, уже committed side effect не повторяется, а неоднозначное execution состояние сохраняет uncertainty до reconciliation.

## Фактический результат

Targeted Stage 6.6 tests, связанные Stage 6 regression checks, project checks и полный pytest suite прошли успешно на указанном snapshot.

## Метрики

Correctness baseline: один trace ID на Task lifecycle; ordered persistent trace survives restart; zero replay already-succeeded side effects; executing → uncertain вместо догадки об успехе; полный regression остаётся зелёным.

## Доказано

Stage 6 имеет persistent unified causal trace и system-owned restart coordinator, который координирует существующие recovery boundaries без создания нового владельца Task/Goal/Execution/Sleep state.

## Не доказано

Stage 6.6 не доказывает полезность adaptive routing, `request_more_context`, автоматическую калибровку Internal State, semantic writes или полный Stage 6 end-to-end acceptance corpus. Эти вопросы остаются для 6.7–6.8.
