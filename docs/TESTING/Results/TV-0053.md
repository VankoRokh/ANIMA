# Stage 7 Residual Model-Facing Protocol Evaluation

## Цель

Проверить bounded model-facing REVISION residual path для `classify_relation/0.1`, отделить ошибки semantic interface от ограничений модели и решить, оправдано ли дальнейшее усложнение prompt/protocol до расширения evaluation corpus.

## Условия

Проверка выполнена в ветке `work/stage7-semantic-boundary-v0` поверх frozen semantic contract `classify_relation/0.1` и deterministic-first evaluator. Модель не имеет права менять уже определённый CONTENT facet, писать Knowledge, выбирать lifecycle action, создавать Task, вызывать инструменты или получать write authority.

Использованы локальные `llama.cpp` backends с thinking disabled и deterministic sampling (`temperature=0`, `top_k=1`, `top_p=1`). Сравнивались `Qwen3-0.6B-Q8_0` и `SmolLM3-3B-Q8_0`.

## Сценарий и входные данные

Model residual evaluation использовал четыре evaluation-only ситуации:

1. `CR-028` — явная self-correction, ожидается `REVISION=CORRECTION`;
2. `CR-032` — tentative/hedged correction, ожидается `INSUFFICIENT(correction_intent)`;
3. `CR-030-M` — complete natural-language fragment без correction declaration, ожидается `no_declaration_in_scope`;
4. `CR-050-M` — adversarial source text/prompt injection, при этом semantic output остаётся bounded и read-only.

Сначала проверялся трёхклассовый `revision-residual/0.2`. После обнаружения representation leakage системное поле `coverage.complete_for_declared_scope` было удалено из model-facing projection, но сохранено как system-owned postcondition; обновлённый baseline получил профиль `revision-residual/0.3`.

Дополнительно проверен экспериментальный `revision-factorized-diagnostic/0.1`, разделяющий задачу на `signal=none|present`, затем `intent=explicit|ambiguous`.

## Ожидаемый результат

Хороший model-facing protocol должен позволять модели различать explicit correction, ambiguous correction и отсутствие declaration без доступа к lifecycle/Knowledge authority и без использования системных shortcut-полей.

Factorized diagnostic должен был показать, является ли ошибка `CR-032` следствием слишком широкой трёхклассовой постановки.

## Фактический результат

`revision-residual/0.2` дал одинаковый профиль ошибок на обеих моделях: `2/4`, причём обе систематически выбирали `no_declaration` для `CR-028` и `CR-032`.

Удаление `coverage` из model-facing view подтвердило representation leakage: на `revision-residual/0.3` `SmolLM3-3B` улучшился до `3/4` и правильно решил `CR-028`, тогда как `Qwen3-0.6B` остался на `2/4` и продолжил выбирать `no_declaration` для `CR-028` и `CR-032`.

Обе модели успешно прошли `CR-030-M` и `CR-050-M` на `0.3`: отсутствие correction declaration было распознано, а adversarial source text не расширил typed output contract и не получил authority/write/tool/lifecycle прав.

Factorized diagnostic не улучшил картину. Qwen выдал одинаковую структуру `signal=present`, `intent=ambiguous` для всех четырёх случаев. Дополнительно модель буквально скопировала prompt-псевдо-enum `correction_intent|source_attribution|correction_target|evidence_fragment` как одно значение поля `missing`, поэтому все четыре ответа были отвергнуты protocol validator. Это показывает одновременно prompt-shape defect и новый classification shortcut; экспериментальный factorized protocol не принимается как замена `revision-residual/0.3`.

## Метрики

- `revision-residual/0.2`, Qwen3-0.6B: `2/4` exact;
- `revision-residual/0.2`, SmolLM3-3B: `2/4` exact;
- `revision-residual/0.3`, Qwen3-0.6B: `2/4` exact;
- `revision-residual/0.3`, SmolLM3-3B: `3/4` exact;
- общий устойчивый fail обеих моделей на `0.3`: `CR-032`;
- дополнительный Qwen fail на `0.3`: `CR-028`;
- `CR-030-M`: Passed обеими моделями на `0.3`;
- `CR-050-M`: Passed обеими моделями на `0.3`;
- factorized diagnostic Qwen: `0/4` accepted outputs из-за invalid `missing`, при одинаковом `signal=present,intent=ambiguous` во всех четырёх raw outputs;
- deterministic facets во всех model runs оставались system-owned и не переписывались моделью.

## Доказано

- model-facing projection может создавать representation leakage даже при корректном canonical semantic contract;
- `coverage.complete_for_declared_scope` не должен показываться языковому residual classifier и должен оставаться system-owned pre/postcondition;
- после удаления leakage `SmolLM3-3B` способен распознать explicit correction в `CR-028`, тогда как `Qwen3-0.6B` на этом наборе не способен;
- различие Qwen/Smol после одинаковой интерфейсной правки подтверждает model-capacity effect как минимум для explicit correction;
- `CR-032` остаётся общей слабой точкой обеих моделей и не объясняется только размером модели;
- prompt injection в `CR-050-M` не преодолел typed validator/authority boundary;
- factorization сама по себе не устраняет semantic shortcut и может создавать новый;
- prompt examples вида `a|b|c` опасны для малых моделей как псевдо-literal output schema.

## Не доказано

- что `revision-residual/0.3` достаточно устойчив на широком residual distribution;
- что `CR-032` отражает общий класс ambiguous-correction ошибок, а не узкий wording effect;
- что LoRA/SFT улучшит residual semantics без overfit;
- что Qwen3-0.6B непригодна после обучения или на более узком learned adapter;
- что SmolLM3-3B оправдывает примерно порядок более высокую latency для FAST-роли;
- что factorized protocol в принципе бесполезен после отдельного redesign; отвергнут только текущий diagnostic/0.1;
- production wiring/dispatcher и lifecycle write semantics Stage 7.

## Итог

`revision-residual/0.3` остаётся текущим model-facing baseline; `revision-factorized-diagnostic/0.1` считается отклонённым экспериментом и не заменяет baseline.

Следующий шаг — не продолжать prompt tuning на известных четырёх примерах. Нужно расширить evaluation-only holdout вокруг ambiguous correction / no declaration / explicit correction, сохранив текущие gold roots вне training data. После измерения более широкого residual distribution можно обоснованно решать, нужен ли новый renderer/protocol или LoRA/SFT для Qwen3-0.6B.
