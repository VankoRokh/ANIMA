# Stage 3.3 Selection / Scheduling

## Цель

Подтвердить deterministic bounded selection: одинаковый набор source metadata должен формировать одинаковый порядок WorkItems, соблюдать item/cost budget, исключать ineligible/terminal candidates и не размножать queue при повторном selection.

## Условия

Проверенный snapshot: `6e914fb132b7d6ffc2b56e5ca86d61900a858658`. Проверка выполнена владельцем проекта в локальном checkout.

## Сценарий и входные данные

```bash
.venv/bin/python -m pytest -q \
  tests/test_sleep_storage.py \
  tests/test_sleep_contracts.py \
  tests/test_sleep_selection.py
.venv/bin/python -m pytest -q
bash scripts/check.sh
```

Selection использует только metadata: `SourceRef`, priority, categorical cost и eligibility/terminal flags. Baseline ordering: priority ↓, cost ↑, source kind, source ID. Cost units: cheap=1, normal=2, expensive=4.

## Ожидаемый результат

- один и тот же вход даёт один порядок WorkItems независимо от порядка входного iterable;
- `max_items` и `max_cost_units` не превышаются;
- ineligible/terminal candidates не попадают в queue;
- точные дубли схлопываются, конфликтующие metadata дают явную ошибку;
- повторный selection переиспользует существующие logical WorkItems;
- dangling selected source не оставляет частично записанную queue.

## Фактический результат

Все запрошенные проверки прошли успешно. Combined Sleep suite 3.1–3.3 содержит 45 test cases и завершился без ошибок. Полный `pytest -q` и `scripts/check.sh` также прошли; точное число полного regression suite отдельно не фиксировалось.

## Доказано

`SleepSelector` формирует детерминированную bounded queue по явной cost model и fixed tie-break, не зависит от payload источника и не создаёт второй logical WorkItem при повторном selection того же source/work/processor/version. Выбранные source references валидируются до записи queue, поэтому deterministic input error не оставляет частичную очередь.

## Не доказано

Stage 3.3 не определяет семантику eligibility конкретных source типов, не исполняет WorkItems, не хранит chunk checkpoints и не решает crash/recovery после внешнего side effect. Source-specific eligibility остаётся ответственностью adapter/policy слоя.
