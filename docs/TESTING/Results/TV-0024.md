# Stage 3.7 Derived Results / Provenance

## Цель

Подтвердить persistent DerivedResult как отдельный Sleep-объект с полным прямым provenance до SourceRef, processor/version, transformation history и явной `derived` authority без автоматического превращения результата в raw observation, Memory или CONFIRMED Knowledge.

## Условия

Проверенный snapshot: `3161585ecce5ac1bc1e15bfdbb6705031dd6f53f`. Проверка выполнена владельцем проекта в локальном checkout.

## Сценарий и входные данные

```bash
.venv/bin/python -m pytest -q tests/test_sleep_derived_results.py
.venv/bin/python -m pytest -q \
  tests/test_sleep_checkpoint_resume.py \
  tests/test_sleep_derived_results.py
.venv/bin/python -m pytest -q \
  tests/test_sleep_storage.py \
  tests/test_sleep_contracts.py \
  tests/test_sleep_selection.py \
  tests/test_sleep_processors.py \
  tests/test_sleep_text_consolidation.py \
  tests/test_sleep_checkpoint_resume.py \
  tests/test_sleep_derived_results.py
.venv/bin/python -m pytest -q
bash scripts/check.sh
```

Canonical tests используют synthetic Event SourceRef, реальные CLOSED Memory и CONFIRMED Knowledge, reopen `sleep.db`, collision output reference, missing source перед finalize и полный checkpoint transformation history.

## Ожидаемый результат

- DerivedResult имеет stable `dr_` ID и отдельный `dout_` output reference;
- сохраняются WorkItem/Job, source refs, processor/version, authority и transformation history;
- result доступен после reopen по result ID, WorkItem и output ref;
- DerivedResult commit и перевод WorkItem в `completed` атомарны;
- missing source блокирует completion;
- Memory/Knowledge source и их evidence/provenance не переписываются;
- derived output не получает authority raw observation или CONFIRMED Knowledge автоматически.

## Доказано

DerivedResult является persistent отдельным объектом Sleep. Его прямой source provenance, processor/version и checkpoint references сохраняются после reopen. Result commit и `completed` status являются одной транзакцией `sleep.db`, поэтому состояние «completed без результата» не создаётся. Реальные Memory и Knowledge остаются неизменными, а существующая цепочка provenance Stage 1 продолжает вести от них к исходным Events.

## Не доказано

Stage 3.7 ещё не решает crash/replay координацию внешних эффектов между `sleep.db` и `memory.db`. Он также не доказывает exactly-once применение будущего Memory/Knowledge effect при падении между двумя хранилищами. Это является предметом Stage 3.8 Recovery / Idempotency.
