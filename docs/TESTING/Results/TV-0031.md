# Stage 4.1 Agent Storage / Lifecycle

## Цель

Подтвердить первый persistent слой Stage 4: отдельный `agent.db` должен сохранять идентичность и lifecycle `AgentRun`/`AgentStep`, обеспечивать stable operation identity и не позволять потерять незавершённый execution/recovery obligation при restart или ошибочном terminal transition.

## Условия

Проверка выполнена владельцем проекта после получения изменений из `main` на snapshot `601949c9eea0d80930df9b54088cdb0629ab9c44`. На этом snapshot присутствуют `anima/agent/store.py`, targeted tests `tests/test_agent_storage.py` и исправленный обязательный формат отчёта TV-0030. Проверка выполнялась в существующем локальном окружении проекта без изменения данных рабочего экземпляра.

## Сценарий и входные данные

Выполнены:

```bash
bash scripts/check.sh
.venv/bin/python -m pytest -vv tests/test_agent_storage.py
.venv/bin/python -m pytest -q
```

Targeted сценарии проверяют создание/reopen `agent.db`, один non-terminal Run на Goal, Run interruption/resume/terminal transitions, последовательный AgentStep lifecycle, один non-terminal Step на Run, transaction rollback и SQLite/FK constraints, persistent `AgentOperation`, `request_hash`, idempotency class, `uncertain` recovery state и запрет завершать Step/Run при незавершённой операции.

## Ожидаемый результат

`AgentRun`, `AgentStep` и `AgentOperation` сохраняют stable IDs и последнее committed состояние после reopen; invalid lifecycle переходы отклоняются без частичного изменения данных; один Goal не получает два одновременных non-terminal Runs; один Run не получает два одновременных non-terminal Steps; terminal Run/Step не может скрыть незавершённую operation; полный regression suite предыдущих стадий остаётся работоспособным.

## Фактический результат

Владелец проекта подтвердил успешное прохождение документационной проверки, targeted `tests/test_agent_storage.py` и полного regression suite на указанном snapshot. Ошибок Stage 4.1 после исправления структуры TV-0030 не обнаружено.

## Метрики

На 4.1 отдельный performance baseline не требуется. Зафиксированы только функциональные результаты: targeted Agent storage/lifecycle suite — Passed; полный regression suite — Passed; `scripts/check.sh` — Passed. Latency, CPU/RAM/storage Agent loop измеряются позднее в Stage 4.14.

## Доказано

`agent.db` создаётся и переоткрывается без потери Run/Step/Operation identity; lifecycle и database constraints отклоняют недопустимые состояния; один Goal имеет максимум один non-terminal Run, один Run — максимум один non-terminal Step; `uncertain` operation переживает restart; transaction rollback и foreign keys работают; terminal transitions не могут молча отбросить незавершённую execution/recovery operation. Реализация не требует изменения Goal/Internal State, Memory или Sleep storage.

## Не доказано

4.1 не доказывает ToolDescriptor/Registry, Action/Observation contracts, фактическое исполнение инструментов, Planner/Choice integration, Goal verification или cross-store Agent recovery. Эти свойства относятся к последующим шагам Stage 4.
