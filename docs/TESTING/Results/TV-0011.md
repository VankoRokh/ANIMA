# Stage 1.8 Retrieval

## Цель

Подтвердить deterministic read-only Retrieval для Memory/Knowledge: exact ID,
structured filters, Entity anchors, FTS5, максимум один relation hop и объяснимый
ranking должны возвращать ожидаемые IDs в ограниченном top-k без мутации данных.

## Условия

Проверенный snapshot: `ac2be3d46ea095f59893fb22a900606dbdd52a34`.
Локальная среда владельца проекта: Linux, Python 3.14.4, pytest 9.1.1.
Рабочие данные экземпляра тестами не используются.

## Сценарий и входные данные

```bash
bash scripts/check.sh
.venv/bin/python -m pytest -q
.venv/bin/python -m pytest -v -s tests/test_retrieval.py
```

Canonical corpus включает current/terminal Knowledge, OPEN/CLOSED/MERGED Memories,
SQLite Entity с alias, FTS-only seed и Relations `about/supports/supersedes`.

## Ожидаемый результат

- exact ID возвращает даже terminal historical record;
- обычный current-search не подмешивает merged/superseded/rejected records;
- явный status filter может запросить terminal record;
- alias Entity возвращает связанные Memory/Knowledge;
- FTS отдаёт ожидаемые current IDs;
- relation expansion ограничена одним hop;
- ranking воспроизводим и объясняет каждый сигнал;
- `top_k` соблюдается;
- invalid requests дают определённую ошибку;
- предыдущая регрессия остаётся зелёной.

## Фактический результат

Пользователь подтвердил `check.sh`, полный regression suite и отдельный
`tests/test_retrieval.py` как полностью зелёные на указанном snapshot.

## Метрики

Latency/CPU/RAM отдельно не фиксировались. Stage 1.8 проверяет корректность и
воспроизводимость retrieval; performance baseline остаётся задачей Stage 1.12.

## Доказано

`RetrievalEngine` детерминированно объединяет exact ID, structured filters, Entity
anchors, FTS5 и максимум 1-hop Relations. Результат содержит `kind/id/score/reasons/
record`, current-search по умолчанию фильтрует terminal history, а exact ID и явные
status filters сохраняют доступ к истории. Importance Memory является только малым
bonus и не заменяет relevance signals. Retrieval является read-only слоем.

## Не доказано

Не доказаны Context Builder budgets/consumer policies, crash-idempotency,
end-to-end Stage 1 corpus и масштабирование 1k/10k/100k. Embeddings, semantic
rerank, query expansion, LLM rerank и глубокий graph traversal намеренно не входят
в baseline Stage 1.8.
