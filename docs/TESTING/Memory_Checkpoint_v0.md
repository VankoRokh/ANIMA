# Memory Checkpoint v0 — синтетический эксперимент

**Статус:** экспериментальный тестовый стенд; не часть замороженного Core v0.1. Исходная база: `6ffdc2e49b115968cb5309ea591fa27f1eace6f3` (`release/core-v0.1`). Код находится в отдельной ветке `experiment/memory-checkpoint-v0`.

## Цель

Характеризовать существующую память ANIMA, не проектируя новый Memory-процессор:

1. Получить 22 синтетических события с повторяющимися темами (дверь, вентилятор, CM5), временными разрывами, сменой сессии, служебными и сенсорными событиями.
2. Выяснить, какие события `MemoryProcessor` пропускает, какие создают память, а какие дополняют или связывают существующую.
3. Проверить текстовое извлечение (top-3), привязку к исходным Event и сохранность SQLite после холодного открытия.
4. **Отдельно** вызвать `MemoryLifecycle.close()` и `KnowledgeLayer.create_candidate()` как ручную демонстрацию API, без утверждения, что ANIMA самостоятельно формирует знания или цели.

## Запуск

Из корня репозитория, в экспериментальной ветке:

```bash
.venv/bin/python scripts/run_memory_checkpoint.py \
  --report /tmp/anima-memory-checkpoint-v0.json
```

Скрипт печатает каждое решение MemoryProcessor и топ результатов поиска; завершается строкой `MEMORY_CHECKPOINT_PASS` при выполнении проверяемых инвариантов. `PASS` **не означает** правильной смысловой классификации: результаты поиска и объединения необходимо оценить отдельно.

Все события и базы создаются во временном каталоге и удаляются после теста; отчет остаётся по указанному пути. Существующая память ANIMA не затрагивается.

## Важные границы интерпретации

- Обработчик `MemoryProcessor._select` текущей версии выбирает только `conversation.user`: сенсорные события остаются в сырых Event, но не преобразуются автоматически в episodic Memory этим обработчиком.
- `system.sleep` в корпусе — проверка типа события, **не вызов настоящей Sleep-консолидации**.
- Текстовые сценарии демонстрируют лексическую ассоциацию; не проверяют самостоятельное понимание двери или причинную связь между звуком и механизмом.
- Вызовы `close` и `create_candidate` выполнены тестовой программой, а не системой мотивации.
- Показатели времени на 22 событиях являются только базовой точкой; масштабирование исследуется отдельными сериями 100/1000/10000 событий и сравнением на фиксированном железе.

## Что смотреть в отчете

- `actions`: соотношение `skip`, `create`, `update`, `create_related`.
- `processed`: действие, оценка, обоснование и задержка для каждого события.
- `retrieval`: насколько выдача релевантна теме, не смешиваются ли несовместимые сведения.
- `provenance_event_ids`: воспроизводимость происхождения воспоминания.
- `cold_reopen_pass`: сохранность после переоткрытия хранилища.
