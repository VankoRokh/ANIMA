## Последняя завершённая задача: SW-03

ANIMA получила более надёжное постоянное состояние.

`AnimaState` записывает `data/state.json` через временный файл, `flush`, `fsync` и атомарный `os.replace`. При отказе во время замены прежний файл остаётся нетронутым, а временный файл удаляется.

При загрузке состояние проверяется на структуру, обязательные поля, допустимый статус и типы счётчиков. Повреждённый JSON и несовместимое состояние вызывают понятную ошибку и не переписываются автоматически.

Проверено:

1. Обычная запись сохраняет новое состояние.
2. Имитированный отказ `os.replace` не повреждает прежний файл.
3. Повреждённый JSON отклоняется без изменения исходного файла.
4. Несовместимая структура отклоняется без изменения исходного файла.
5. Полная проверка проекта и восстановление проходят на Python 3.14.4.

Атомарная запись опубликована в commit `df0c164`; валидация и отказные тесты — в `b430c28`.

## Ближайшая задача: SW-04

Валидация событий и журналов.

Цель — определить допустимую структуру событий и JSONL-записей, а также явное поведение при неверных типах, отсутствующих полях и повреждённых строках.

Перед изменением проверить `event_bus.py`, `event_log.py`, `memory_store.py`, `episodic.py` и описание протокола событий.

## После SW-04

Штатная обработка прерывания и явная конфигурация расположения данных. Детали: [Stage 0](Stage_0_Foundation.md), [Backlog](Backlog.md).

Версионирование и миграция схемы `state.json` не вводятся автоматически в SW-03 и требуют отдельного контролируемого решения.
