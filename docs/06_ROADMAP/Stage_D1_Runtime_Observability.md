# D1 — Runtime, Tests & Observability

## Goal

Отделить выполнение ANIMA от конкретного интерфейса и создать минимальный диагностический/test harness, на котором можно надёжно строить следующие когнитивные этапы.

## Observable result

Один и тот же сценарий можно запустить без интерактивного CLI, получить структурированный результат и автоматически проверить состояние экземпляра, события и ошибки, не трогая реальные пользовательские данные.

## Required work

- [ ] Выделить runtime/controller между `main.py`, жизненным циклом и интерфейсами.
- [ ] Добавить headless/scenario entrypoint для тестов.
- [ ] Ввести структурированный диагностический snapshot состояния и ключевых событий.
- [ ] Создать test harness с временным `ANIMA_DATA_DIR`.
- [ ] Перенести ключевые проверки Stage 0 в постоянный regression suite.
- [ ] Добавить измерение длительности операций; базовые RAM/CPU метрики — если доступны без тяжёлой зависимости.
- [ ] Определить формат понятного человеку trace для наблюдения процесса теста.
- [ ] Не строить GUI до появления реальной потребности.

## Test scenarios

1. Headless-сценарий создаёт новый временный экземпляр, проводит сессию и возвращает структурированный результат без `input()`.
2. Тот же базовый сценарий через CLI и headless приводит к эквивалентному состоянию данных.
3. Regression: restart, corrupted state, invalid JSONL, Ctrl+C/EOF-equivalent shutdown, `ANIMA_DATA_DIR`, recovery/continuity.
4. Ошибка внутри сценария показывает этап/событие, на котором произошёл сбой, а не только общий traceback.
5. Test harness гарантированно не пишет в рабочий `data/`.

## Regression scope

Все свойства, закрывшие Stage 0.

## Acceptance criteria

- regression suite проходит одной командой;
- headless запуск не зависит от терминального интерфейса;
- ключевые состояния и переходы доступны в структурированном виде;
- тесты используют изолированные временные данные;
- результат не требует ручного чтения JSONL для понимания причины падения.

## Evidence to save

Финальный D1 validation: вывод regression suite + один полный диагностический trace headless-сценария + сравнение итогового состояния CLI/headless.

## Deferred

Полноценный GUI/TUI, telemetry server, визуальные графики и удалённая отладка. Они вводятся только по измеренной необходимости.
