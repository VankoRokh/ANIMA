# План развития ANIMA

Переход между этапами определяется не количеством написанного кода, а **доказанным свойством системы**. Каждый Stage имеет наблюдаемый результат, набор проверок и критерий закрытия.

Аппаратные закупки откладываются до момента, когда программный прототип упрётся в измеренные ограничения ноутбука/VM.

| Этап | Что должно быть доказано | Статус |
|---|---|---|
| [D0 — Documentation](Stage_D0_Documentation.md) | Контекст проекта восстанавливается из репозитория | Complete |
| [0 — Foundation](Stage_0_Foundation.md) | Экземпляр сохраняет идентичность, историю и восстанавливается после переноса | Complete |
| [D1 — Runtime, Tests & Observability](Stage_D1_Runtime_Observability.md) | Поведение можно запускать headless, наблюдать структурированно и проверять воспроизводимыми сценариями | Complete |
| [1 — Cognitive Memory](Stage_1_Memory.md) | Память извлекает нужный опыт с проверяемым происхождением и ограниченным контекстом | Planned — следующий |
| [2 — Internal State](Stage_2_Internal_State.md) | Внутреннее состояние причинно и наблюдаемо влияет на выбор | Planned |
| [3 — Sleep](Stage_3_Sleep.md) | Опыт консолидируется прерываемо, воспроизводимо и в измеренном бюджете | Planned |
| [4 — Agent](Stage_4_Agent.md) | ANIMA выполняет ограниченную задачу через инструмент и проверяет результат | Planned |
| [5 — Virtual ANIMA](Stage_5_Virtual_ANIMA.md) | Система длительно и воспроизводимо работает на обычном ПК/VM | Planned |
| [6 — Cyberdeck](Stage_6_Cyberdeck.md) | Измеренная нагрузка перенесена на автономное устройство | Planned |
| [7 — Embodiment](Stage_7_Embodiment.md) | Физические модули заменяемы, диагностируемы и безопасно переживают отказ связи | Planned |

## Принципы порядка

1. Сначала наблюдаемость и тестируемость, затем усложнение поведения.
2. Детерминированный baseline создаётся до внедрения LLM/обучения, если задача это позволяет.
3. Новая модель или алгоритм вводятся только там, где есть benchmark и baseline для сравнения.
4. GUI отладки не является отдельной целью: он появляется, когда диагностический слой уже стабилен и текстовых представлений становится недостаточно.
5. Аппаратная архитектура выбирается по измерениям Stage 5, а не по предполагаемой мощности.

## Как закрывается Stage

Страница каждого этапа фиксирует:

- Goal;
- Observable result;
- Required work;
- Test scenarios;
- Regression scope;
- Acceptance criteria;
- Evidence to save.

Показательный результат после закрытия переносится в [Test Results](../07_EXPERIMENTS/Test_Results.md). История commit остаётся в Git.
