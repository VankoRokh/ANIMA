# Идентичность и непрерывность

Принятый принцип: данные конкретного экземпляра должны переноситься между заменяемыми компонентами. Минимальная постоянная идентичность реализована; расширенные правила происхождения, копирования и миграции остаются Draft.

## Различаем три сущности

| Сущность | Содержание | Сейчас |
|---|---|---|
| Identity | ID экземпляра, происхождение, версия схемы, устойчивые настройки | Минимально реализована: `identity.json` содержит UUID4 instance_id, schema_version и created_at |
| Runtime State | Сессия, awake/sleeping, время запуска и счётчик событий | AnimaState, `state.json` |
| Memory | История событий и выбранный опыт | `events.jsonl` и `memories.jsonl` |

Название ANIMA внутри state.json не является уникальным ID экземпляра. Для этого используется instance_id из `identity.json`. Эти файлы находятся в каталоге экземпляра: по умолчанию `<project>/data`, либо в пути, заданном через `ANIMA_DATA_DIR`.

## Перенос и копия

Для переноса нужно остановить запись, сделать целостную резервную копию каталога экземпляра, проверить её и восстановить на новом оборудовании. Запуск без существующих данных в выбранном каталоге создаёт новое состояние. Контрольная проверка 2026-10-13 подтвердила, что каталог можно восстановить в другой путь и новую установку кода, продолжить с тем же `instance_id` и не изменить исходную копию.

Одновременный запуск двух копий не решает, какая из них считается продолжением. Для будущего распределённого Fast/Deep нужны происхождение записей, IDs событий и правила конфликта. Эти правила ещё не разработаны.

## Практические критерии

После переноса должны сохраняться ID, история опыта и настройки; формат должен быть совместим, а дальнейшие события — добавляться без потери и дублирования. Сохранение instance_id после перезапуска и переноса уже проверено; правила конфликтов между копиями ещё не разработаны.

## Что не следует обещать

Сохранённая память не гарантирует одинаковое поведение после смены модели. Для воспроизводимости будущего экземпляра потребуется также фиксировать версии моделей, конфигурацию и правила обработки.

Сменный физический носитель «личности» остаётся аппаратным направлением; горячее извлечение без остановки не спроектировано.
