## R-08 — принятое решение владельца

**15 ноября 2026:** утверждены ограниченные ресурсные границы для фиксированного ноутбучного сценария. Исходный runner по-прежнему честно печатает `performance_status=MEASURED_NOT_SLO_GATED`, потому что он **измеритель**, а не механизм принятия задним числом. Отдельное решение и точные источники — [R-08 Resources](resources.md).

| Ноутбучный сценарий (SHA `6203e3f`) | p95 report | Пиковая RSS | Корректность |
| --- | ---: | ---: | --- |
| 128 uniform | **9.756 мс** | **34036 KiB** | `FUNCTIONAL_GATE_PASS` |
| 160 plain | 19.184 мс | 34732 KiB | 8 Memory / 0 смешанных тем |
| 160 labeled | 20.331 мс | 34800 KiB | 8 Memory / 0 смешанных тем |

Предложение об улучшении `Memory.content` и дальнейшем исследовании семантического поиска отложено на следующие версии. **Отдельная Memory с 20 source Events не гарантирует полноты компактного Context** (512 символов); исходные события остаются доступны в Event Retrieval. Улучшать LLM, метапамять и Stage 7 до релиза v0.1 не требуется.

## R-09 — условия завершения

1. Выбрать окончательный commit и сохранить его полный Git SHA + состояние checkout.
2. Выполнить `bash scripts/check.sh` и **полный** `python -m pytest -q` на Python 3.12, 3.13, 3.14 для этого дерева.
3. На каждом окружении повторить функциональный 128-event release gate, проверить `FUNCTIONAL_GATE_PASS`, `ALL_ACCOUNTED`, `identity_reopen`, `event_index_complete`.
4. Зафиксировать фактический checkout SHA в CI: PR merge SHA **не** подменяет SHA ветки или релизного тега. Сохранить ссылки на CI runs и сырой JSON.
5. Выполнить локальную финальную проверку Linux/Python 3.14.4 на том же релизном SHA; задокументировать расхождения, если они возникнут.

Успех в CI на 3.12/3.13/3.14 не является доказательством работы на Pi; notebook performance bound проверяется на ноутбуке по отдельной методике [R-08](resources.md).

## Решение владельца по R-10

**Релиз не принят.** R-08 принят в указанных границах, но R-09 на окончательном Git tree ещё требуется. После R-09 записать дату решения, профиль, точный commit/tree, результаты всех обязательных проверок и остаточные ограничения. Только после этого создать тег `v0.1`; не делать выпуск автоматически.
