# R-08 — ресурсная приёмка ANIMA v0.1 Foundation

**Решение владельца: 15 ноября 2026 года. Статус: ACCEPTED_SCOPED.** Утверждены ограниченные критерии для штатного release-профиля на фиксированной ноутбучной нагрузке. Это **не** универсальный SLO системы и не тест масштабирования.

## Норматив и условия

Для `python -m scripts.run_release_v01_gate --events 128` в **чистом** checkout на основном ноутбуке Linux x86-64, Python 3.14.4, без модели, внешних сенсоров и Godot:

| Показатель | Критерий для указанного сценария | Метод измерения |
| --- | ---: | --- |
| Задержка `report`, p95 | **строго менее 100 мс** | `report_latency_ms.p95` |
| Пиковая RSS процесса Python | **строго менее 256 MiB** (=262144 KiB) | `peak_self_rss_kib` |
| Функциональная целостность | `FUNCTIONAL_GATE_PASS` | `test_status` |
| Источники и индекс | `ALL_ACCOUNTED`, `event_index_complete=true` | `source_links`, `event_index_complete` |
| Чистота источника | `checkout_clean=true` и известный полный SHA | `source_sha` |

**Единицы:** p95 — миллисекунды одного `report`, RSS — KiB на Linux; `ru_maxrss` отражает максимум **целого процесса**, а не изолированное потребление Core. Значения не являются гарантией на иной машине, при параллельной нагрузке или при базе другого размера.

Встроенный runner остаётся честным первичным измерителем и печатает `performance_status=MEASURED_NOT_SLO_GATED`. **Решение о нормативе принимается этой карточкой**, а не задним числом изменённым JSON или автоматически изменённым полем runner.

## Принятое ограничение Memory

`MemoryProcessor` после PR #9 консервативнее объединяет эпизоды: единичный общий токен или повторяющаяся разметка не должны приводить к склейке разных явно обозначенных тем. Это **эвристика**, а не универсальный semantic classifier.

`RuleBasedComposer` ограничивает `Memory.content` бюджетом **512 символов**. Объект Memory может иметь 20 или больше исходных Events, но компактный Context не обязан перечислять все факты: часть содержимого может состоять из маркеров и последних фрагментов, а более ранние детали отсутствовать. **Доступность raw Event через Event Retrieval не равнозначна полноте Context.**

В v0.1 это принимается как ограничение **с сохранением исходных Events и Provenance**. Не требуется универсальная консолидация, семантический recall по произвольным синонимам или исправление старых уже смешанных Memory. Следующее развитие Memory должно отдельно исследовать: отделение метаданных от семантического контента; представление эпизодов с явно сохранёнными source ID; стратегии сжатия с ограничением потерь; качество поиска по незнакомым формулировкам; миграцию исторических смешанных групп. Это **исследовательский backlog**, не скрытое обязательство v0.1.

Исследовательская методика, два корпуса и ограничения интерпретации: [R-08 diversity probe](../../RESEARCH/v01-r08-diversity-probe.md).

## Что не доказано

- Длительная работа на сотнях тысяч событий, рост SQLite/FTS и устойчивость p95 при больших объёмах.
- Семантическая полнота `ContextBundle`, точность ответов LLM и способность различать любые неразмеченные темы.
- Работа на Raspberry Pi, при реальном отключении питания, при сетевых датчиках, Godot или произвольных внешних эффектах.
- Норматив для смешанного 160-событийного корпуса: его показатели измерены для диагностики, но **не являются новым обязательным performance-gate**.
