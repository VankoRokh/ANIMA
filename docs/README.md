## Статусы и терминология

Не смешивать **пять разных понятий**:

- **Историческая стадия (Stage)** — доказанное свойство на момент отдельного этапа. Старые `Complete / Planned / Stopped` остаются в [`project.json`](project.json).
- **Релиз** — конкретный зафиксированный набор функций, принимаемый через [отдельный контракт](RELEASES/ANIMA_v0_1_Release_Contract.md). Завершение Stage не равнозначно выпуску версии.
- **Реализованный модуль** — код и интерфейсы существуют, но они могут быть необязательными для базовой сборки.
- **Проверенный эксперимент** — лаборатория прошла свои тесты, но это не значит, что её механизм включён в production.
- **Идея/исследование** — предложение без принятого релизного обязательства.

Например, Stage 4 `Stopped` не отменяет полезности Executor/Verification, а Stage 7 `Planned` не запрещает выпуск детерминированного v0.1. Историческое `current_stage=7` не является текущим списком задач релиза.

## Правила ведения

- **Один факт — одно каноническое место:** цели версии → `RELEASES` и `versions/`; история и статус Stage → `project.json` / `history/`; действующие механизмы → `ARCHITECTURE`; исследования → `RESEARCH`; первичные доказательства → `TESTING`; причины выбора → `DECISIONS`.
- Обзорные страницы могут ссылаться на один и тот же компонент, но не должны создавать альтернативные версии его контракта.
- Исходные TV-отчёты и проверенные commit не исправляются задним числом. Неподтверждённые результаты помечаются явно.
- Генератор `scripts/update_docs.py` меняет только `AUTO:...` блоки; не редактировать их вручную. Синтаксис, ссылки и доступность страниц проверяет `bash scripts/check.sh`.
- Если предлагается изменить фундаментальную границу полномочий или формат хранения, сначала определить инвариант, миграцию и критерии приёмки. Развитие компонентов допустимо, но не через скрытую несовместимость.
- Будущие релизы сохраняются как концепции. Полные этапы и приёмка создаются **только для выбранного следующего релиза**.
- Исторические черновики, пока на них ссылаются тесты и отчёты, не перемещать механически: [архивная карта](ARCHIVE/Development_Snapshots.md) и Git сохраняют путь к первичным данным.

**Для обновления документации:** `python3 scripts/update_docs.py --check`, затем `bash scripts/check.sh`. Более подробно: [эксплуатация](OPERATIONS/README.md#ведение-документации).
