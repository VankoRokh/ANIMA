## Как запускать

Из корня репозитория:

```bash
PYTHONPATH="$PWD" .venv/bin/python -m pytest -q -rx \
  tests/test_v02_h0_foundation_contracts.py
```

В базовой версии ожидаются **XFAIL**, поскольку тесты утверждают целевое поведение *после* исправления, которого в v0.1 ещё нет.

Метки `xfail(strict=True, raises=AssertionError)` намеренно:
- отражают подтверждённый дефект как ожидаемое несоответствие;
- не маскируют неожиданные ошибки подготовки окружения;
- превращаются в `XPASS` при исправлении; **strict XPASS останавливает gate**, пока в ревью не будет удалён marker `xfail`.

Внимание: до прогона нельзя считать девять сценариев независимо воспроизведёнными на этой ветке. Код тестов проверен на синтаксис, но не исполнялся против целого репозитория в окружении автора пакета.

## Карта тестов

| Тест | Инвариант | Рабочая группа |
|---|---|---|
| N1 | Конфликтующие Entity ID не приводят к безусловному merge | H4 |
| N2 | Неактивная Entity не получает действующий `about` только по ID | H4 |
| N3 | Нельзя создать `confirmed` Knowledge без Evidence | H2 |
| N4 | Удаление Memory не оставляет живой `supports` без источника | H2 |
| N5 | Истёкшая Relation не является актуальной | H3 |
| N6 | Правка середины индексированного JSONL не даёт ложное `complete` | H1 |
| N7 | Незаполненная до LF JSONL-запись не считается завершённым Event | H1 |
| N8 | Терминальные FTS seeds не скрывают актуальную Memory | H3 |
| N9 | Отсутствующий обработанный Raw не скрывается под `complete` при Context | H1 |

N6, N7 и N9 **намеренно повреждают только временные файлы** в `tmp_path`. Не запускать подобные сценарии на пользовательских данных. Они моделируют нарушения, а не реальные испытания выключения питания.

## Проверки и границы

- Не изменять принятый snapshot v0.1.
- Не менять `anima/` до завершения и воспроизведения H0.
- Не добавлять новые функции памяти в v0.2.
- Не удалять Raw Events автоматически.
- Не делать Raspberry Pi 5 обязательным gate стабилизации.
- Проверить конечное состояние SQLite/JSONL, корректность error/degraded и отсутствие silent corruption.
- Если тест ожидаемо XFAIL по другой причине (или FAIL/ERROR), сначала уточнить fixture, а не маскировать новое поведение.
