# ANIMA v0.2 — H1.1 / EventLog tail integrity

**Статус:** исправление внесено в рабочую ветку, локальное исполнение против репозитория ещё не подтверждено.

## Цель

Устранить R1-S1 N7: `EventLog.load_events()` принимал корректный JSON без завершающего LF как завершённый Event, хотя `EventRetrieval` оставлял такую запись в состоянии `partial`. После следующего append две записи могли слиться в некорректную строку.

## Изменения

- `EventLog.load_events()` отклоняет любую физически незавершённую JSONL-строку; `newline="\n"` не позволяет распознать одинокий CR как LF.
- `EventLog.write()` проверяет последний байт файла перед append, **включая случай с ранее закешированными Event IDs**.
- При нарушении возвращается `ValueError`; журнал не обрезается и не переписывается.
- Новые записи используют LF; существующий CRLF остаётся читаемым.
- Проверка H0 N7 теперь обычный `PASS`, а не `XFAIL`.
- Добавлены семь независимых тестов `tests/test_v02_h1_eventlog_tail.py`.

## Запуск на ноутбуке

Из корня репозитория:

```bash
git status --short

PYTHONPATH="$PWD" .venv/bin/python -m pytest -q -rx \
  tests/test_v02_h0_foundation_contracts.py \
  tests/test_v02_h1_eventlog_tail.py
```

**Целевой результат:** `8 passed, 8 xfailed` (1 H0 N7 + 7 H1.1 = 8 PASS; остальные 8 H0 = XFAIL).

Далее:

```bash
PYTHONPATH="$PWD" .venv/bin/python -m pytest -q
```

Проверки синтаксиса и исполнения на Python 3.12 и 3.14 рекомендуются; Raspberry Pi не является обязательным gate.

## Проверяемые сценарии

1. Полный журнал: append, reopen, чтение индексом.
2. Синтаксически корректный JSON без LF: чтение и append отклоняются.
3. Кеш ID: append отклоняется и без повторного полного чтения.
4. Частично записанный JSON: никаких автоматических удалений байтов.
5. Recovery отклоняет незавершённую запись до публикации Memory.
6. Индекс сообщает `partial` и Raw loader отклоняет ту же незавершённую запись.
7. Существующий CRLF остаётся совместимым.

## Границы гарантий

Это **fail-closed**, а не автоматический ремонт. Повреждённый хвост блокирует нормальный запуск/append до отдельного безопасного восстановления из копии или явно разрешённой операции.

H1.1 **не обеспечивает**:
- физическую долговечность при внезапном отключении питания (`fsync` отдельно не добавлен);
- атомарную транзакцию между JSONL и SQLite;
- защиту от параллельной записи некооперирующихся процессов;
- обнаружение повреждения середины журнала (N6);
- сверку ранее финализированных Raw Events после их исчезновения (N9).

Эти темы остаются отдельными этапами H1.2 и H1.3. Стратегия исправления не должна самопроизвольно удалять исторические Events.
