# ANIMA

**Autonomous Neural Intelligence & Modular Architecture**

ANIMA — исследовательский проект модульного агента с сохраняемым опытом.
Цель — система, которая продолжает работу после перезапуска и замены компонентов,
помнит происхождение опыта и позволяет наблюдать, почему она действует.
Языковая модель рассматривается как заменяемый когнитивный компонент такой системы,
а не как её память или главный runtime loop.

Главный вопрос: можно ли развивать память, cognition и действия агента, сохраняя
проверяемую непрерывность данных при замене моделей и оборудования?
Текущая задача — получить проверенный экземпляр ANIMA v0.1 без обязательных LLM,
Godot и Raspberry Pi. История уже завершённых стадий, реализованная архитектура
и планы будущих версий документируются **раздельно**.

## Активная версия: ANIMA v0.1 Foundation (кандидат)

Главный путь разработки — создание **постоянного детерминированного экземпляра** без обязательных LLM, Godot, Raspberry Pi и периферии. Цели и приёмка — в [релизах](docs/RELEASES/README.md); [полная история Stage D0–6](docs/STAGES/README.md) и [карта механизмов](docs/ARCHITECTURE/README.md) отделены от рабочего плана. Проверенный владельцем ноутбука срез `d77974b` прошёл локальную функциональную приёмку; **финальный релиз ещё не объявлен**.

Запуск из новой пустой директории данных (Linux, Python 3.12+):

```bash
.venv/bin/python -m anima.release_v01 --data-dir /tmp/anima-v01-instance
```

Протокол — по одному JSON-объекту на строку: `{"op":"report","text":"..."}`, `{"op":"search_events","query":"..."}`, `{"op":"context","query":"..."}`, `{"op":"status"}`, `{"op":"stop"}`. Базовый профиль не содержит исполнительных полномочий. Небольшой SQLite sandbox для проверки Goal/Task подключается **только** при явном `--sandbox-door` и в отдельном экземпляре.

Существующие Stage ниже описывают **историю развития и архитектурные исследования**; их `Complete/Planned` не являются критерием выпуска v0.1. Будущие релизы пока не детализируются.

## Принципы

- Данные экземпляра отделены от общего кода и переносимы между совместимыми компонентами.
- Модули имеют проверяемые границы; логический модуль не требует отдельной платы.
- LLM используется как сменяемый когнитивный механизм; системные сервисы владеют
  памятью, событиями, состоянием, проверкой и исполнением.
- Сначала минимальный наблюдаемый контур и deterministic baseline, затем усложнение
  после измеренной необходимости.
- Принятый замысел, гипотеза и подтверждённая реализация различаются явно.
- FAST предназначен для оперативного reasoning с компактным контекстом; DEEP — для
  более дорогого анализа. Они используют общую память и историю ANIMA, а не являются
  отдельными личностями.
- Hardware и физическая форма выбираются по измеренному workload; корпус не является
  отдельной смысловой целью проекта.
- Код и воспроизводимые результаты предназначены для открытого развития;
  лицензию проекта и права на будущие модели ещё нужно определить.

Сохранение «личности» здесь — перенос идентичности, опыта и правил обновления;
само по себе оно не доказывает субъективное сознание.
[Существенные решения и причины](docs/DECISIONS/README.md).

## Начать работу

Linux/Bash, Git и Python 3.12+. Рабочий контур использует стандартную библиотеку;
для тестов нужен pytest из requirements-dev.txt.

```bash
bash scripts/setup.sh
bash scripts/check.sh
.venv/bin/python -m pytest -q
bash scripts/run.sh
```

Run создаёт или продолжает локальный экземпляр. Его данные резервируются
отдельно от Git. Восстановление, внешний ANIMA_DATA_DIR и наблюдение тестов —
в [Operations](docs/OPERATIONS/README.md) и [Testing](docs/TESTING/README.md).
Полная навигация: [документация](docs/README.md).
